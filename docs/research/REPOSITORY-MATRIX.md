## Legend

Disposition (five value vocab):
- STUDY_ONLY: read the technique, copy nothing. Either the license forbids reuse, Project Studio already implements it, or the feature is out of contract scope.
- CLEAN_ROOM_REIMPLEMENT: reimplement the behavior in Project Studio TypeScript/Phaser from the described pattern, never from the source text. Reserved for patterns whose feature is authorized (or will be at D2/facilities).
- ADAPT_PERMISSIVE_CODE: directly adapt licensed code. Not used in this corpus. Every candidate with useful code is copyleft (GPL/AGPL/MPL) or wrong engine, so this disposition never fired.
- REJECT: an explicit anti pattern to avoid; cited as the boundary Project Studio draws.
- ADOPT_ASSET: import an art/audio asset directly. Not used. Every open art set here is copyleft (GPL/CC-BY-SA) or license unclear, none clears the Asset Lab original/CC0 bar.

License risk: LOW (permissive MIT, safe to study freely), MEDIUM (copyleft code or share alike art, study only, no code/art lift), HIGH (AGPL network copyleft, MPL entangled with retail assets, or GPL commercial product; hard legal no go for any code or asset reuse). Every disposition above stays clean room regardless of risk; no line of code and no asset crosses into Project Studio.

Project use: the specific D1 surface each pattern ties to (StudioLotSnapshot fields, iso.ts, the nine BuildingIds, AttentionState/StageState, navigation.ts, sceneSeed, D1-A identity package, M0A byte identity).

## Priority order of repositories for Project Studio

This is the canonical repo level ranking, mirrored in the Executive conclusion (Section A) of the blueprint. It weighs how directly a repo serves Project Studio's near term work (the D1-A Studio Identity Package, the `studioLotSnapshot` selector, the fixed iso lot) together with how clean its license posture is for a small team that must never contaminate a closed product. It is a different and finer metric than the coarse 1 to 5 Priority column in the matrix rows above, which is a per repository relevance tier, not an ordered rank.

1. CorsixTH. The prioritized single mood icon is precisely the algorithm the `studioLotSnapshot` selector needs to emit one attention marker per building deterministically; declarative object footprints plus named anchors are the interaction anchor reference; and MIT is the cleanest license in the readability set. Highest leverage plus cleanest license.
2. OpenTTD + OpenGFX. Manifest driven, checksummed, swappable base set (`.obg`) and palette recolour branding map directly onto the D1-A identity slice, and OpenGFX is the worked example that open does not mean CC0 (it is GPL copyleft).
3. Augustus. Function pointer overlay abstraction plus layered building state readability are the ready made grammar for the AttentionState union and the D1-A package; the footprint versus top depth split is the lightweight escalation for multi tile stages. AGPL and retail asset dependent, so study only, but the highest density of directly applicable readability patterns.
4. OpenRCT2. Best reference for iso depth escalation, placement ghost, and render/pick parity, and the cleanest legal precedent for the code and art separation Project Studio already practices.
5. FreeSO. The reference for future character activity: interaction slots, routing to slot, and wall cutaway interiors, plus independent corroboration of the Asset Lab shared skeleton direction. Carries a confirmed Nintendo IP red flag (`Mario.dll`, SM64 code) to stay clear of.
6. IndustryIdle. Same language (TypeScript) and the clearest sim truth vs optional culled sprite split for future production flow animation, plus browser scale performance levers. GPL, study only.
7. Egregoria. Its determinism hashing and headless parity tooling validate and could inform the M0A byte identity work; mostly corroboration of a boundary Project Studio already owns.
8. unknown-horizons. Mature declarative building/tier/threshold data schema; a future reference for facilities and eras, not a now build. GPL code with CC-BY-SA share alike content.
9. GDQuest godot-2d-builder. Clean MIT construction ghost pattern, but wrong engine (GDScript/Godot) so nothing is code portable; pattern reference for a future expansion preview.
10. IsoCity. Confirms `iso.ts` math against a second independent implementation and supplies one crisp REJECT (renderer owns truth); a confirmatory analogue, not a source of new capability.
11. Citybound. Corroborates the snapshot boundary and seeded procedural detail, but AGPL, dormant, and procedural 3D; low actionable yield.
