**Status:** Phase-2 candidate design, inference only. Not implementation. Every number is a PAPER HYPOTHESIS. ## 3. StoryProperty and minimal-rights model

**Finding base.** Accepted code has no property/rights entity at all: `FilmIdentity.studioId` means *creator*, is validated against historical employment, and must never be read as *current owner* (04-code-audit.md F "FilmIdentity.studioId ... CREATOR"; 00-KEY-FINDINGS.md:211). `conceptId` is the one durable thread linking script → production → film → run (types.ts:154-163, 680-700; screenplay.ts:15-40; 00-KEY-FINDINGS.md:221) and the code already distinguishes studio-original from market-sourced material: `isOriginalScreenplay(blueprint)=ordinal!==null`, `ScreenplayProvenanceView.origin:'original'|'pool'`, `ACQUIRED_SCREENPLAY_LABEL` (screenplay.ts:305-345; 00-KEY-FINDINGS.md:147, 238). Approved documentation already assigns P16 sole authority over "the durable StoryProperty and Film Library identities ... origin-work relationships, chain of title, rights ownership, rights licensing ... dated ownership history" and forbids inferring or bulk-minting a property "from title, genre, cast, release order, current studio" (P11→P12 consumer contract §15; 00-KEY-FINDINGS.md:138-139). Real-world law confirms the Owner's split is the actual legal structure: a film is a derivative work whose copyright never absorbs the underlying property (U.S. Copyright Office Circular 14; 10-rights-law.md F; 00-KEY-FINDINGS.md:269).

**Recommendation (inference).** StoryProperty is a new, additive root — not a widened frozen leaf — keyed by an exact, explicitly-minted `propertyId`. Anchor it on `conceptId`/`productionId` provenance (never as a join key) with fields: `title/originalTitle`, `origin{kind: 'studio-original'|'externally-sourced', creatorStudioId (IMMUTABLE), creatorTalentIds (IMMUTABLE), mintedWeek}`, `works: FilmId[]` (append-only, `FilmId===productionId`). Ownership and licence state are derived from a separate dated relation ledger, never stored on the property record itself — this satisfies both P15 §13.1's "never widen a frozen historical leaf" rule and the contract §15 exact-ID minting requirement (00-KEY-FINDINGS.md:235).

Mint point: **at Greenlight** (recommended over Release or Commission) — provenance is frozen before any acquisition can move a production; every released film already has its property when P17 needs it; a cancelled production still leaves a legible "unproduced property." This is inference, not settled; Release and Commission are real alternatives and the exact mint point is listed as a remaining Owner decision (§20).

Rights bundle: four kinds, matching what every real deal and every disciplined comparator actually uses (10-rights-law.md design implications; 00-KEY-FINDINGS.md:290; 08-realworld-ma.md design implications; 00-KEY-FINDINGS.md:639):
- **R1 PROPERTY** — the underlying Story Property. Sellable, single holder.
- **R2 FILM/LIBRARY** — ownership of a specific released work. Sellable, single holder, separable from R1 (Turner/MGM 1986; DreamWorks/Soros 2006; 00-KEY-FINDINGS.md:274-275, 621).
- **R3 CONTINUATION** — sequel/remake/spin-off authority. Licensable only, never sold apart from R1 (Sony/Marvel; Lucas/Fox; 00-KEY-FINDINGS.md:273, 618, 630).
- **R4 CROSS-MEDIA** — future TV/cross-media exploitation (P18-owned execution). Licensable only, and **forbidden to grant before P18 exists** — no unearned upfront fee for a right nothing can yet exercise.

No territory/window/exclusivity sub-splits: every comparator and every real case converges on exactly this granularity, and no observed decision anywhere in the evidence needed finer slicing (10-rights-law.md; 00-KEY-FINDINGS.md:272, 276, 363). This directly answers assignment §2.B: rights are divisible enough to matter, not so granular they become clerical.

## 4. Film-library value

**Finding base.** The original's "Movies 24%" studio-rating term is a Success-weighted, explicitly *decaying* aggregate ("a town with a staggeringly short memory ... the impact of individual movies decays over time," Prima p.46; 00-KEY-FINDINGS.md:25) — the opposite of durable library value; assignment framing that treats it as library-value precedent is CORRECTED. Accepted code confirms a film's economic life ends at `TheatricalRun` completion with zero further cash flow (03-authority-domains.md; 00-KEY-FINDINGS.md:95). Real deals (RKO/C&C 1955 TV rights, MGM/Sony 2004 DVD, Amazon/MGM 2021 streaming, Miramax/Netflix-Hulu 2011) all show library cash appearing **only when a downstream distribution window exists** (08-realworld-ma.md; 00-KEY-FINDINGS.md:641). Comparators agree: The Executive ties library revenue to home-entertainment deals, Moviehouse deliberately caps it as "a slight secondary source," Hollywood Animal parks TV licensing for Act 2 (00-KEY-FINDINGS.md:337, 351, 365).

**Recommendation (inference).** Library value is a **formula-versioned valuation read-model only** (like existing `rankSnapshots`-style derived views) — never a P11 ledger fact, never added to Cash, never a weekly income line. It is a strategic/historical input to Book Net Worth and Enterprise Valuation (§14) computed from count/quality of owned R1/R2 rows, counted **once each** to avoid double counting sequel potential (R1) against catalog value (R2). No perpetual weekly library cash exists before an owning P18 distribution/media system is authorized — this is the assignment's own §2.C instruction and is independently confirmed by every comparator and every real case reviewed.

## 5. Acquisition operating model (A/B/C/D against the six criteria)

**Finding base.** A single accepted-code fact governs most of this section: every entered rival must have a live `RivalBusiness` that ticks unconditionally every week (staffing, greenlight, release, payroll, overhead) with **no representable "operations ended" state** — `hollywoodValidation.ts:331` enforces a strict bijection between entered-rival identities and live business rows, and `hollywoodTick.ts:221-288` has no conditional branch to skip one (13-gap-model-d-six-criteria-evaluation-table.md F1; 00-KEY-FINDINGS.md:714). This one gap governs 5 of the 24 cells in the required six-criteria × four-model table: Models A, C and D can reach LOW management-burden / HIGH AI-compatibility only *once a terminal business state ("H5") ships*; **Model B fails structurally and unconditionally**, because B's entire premise (the business keeps operating) means the H5 fix that rescues A/C/D never applies to it, and its account/production arrays would grow forever — compounding a save-growth budget the accepted game already exceeds (49.6 MB at week 8791; 04-code-audit.md F "save growth"; 00-KEY-FINDINGS.md:231).

Comparator evidence independently converges on the same conclusion. Model B (autonomous subsidiary) is the comparator failure mode across three unrelated titles: Mad Games Tycoon 2 subsidiaries are "a fiction ... just a timer emulating that," Capitalism Lab AI-CEO subsidiaries "do literally nothing," Software Inc. subsidiaries are "a source of never ending cash" (05/06-comparators; 00-KEY-FINDINGS.md:342, 409, 415-416). Model C is comparator-validated and playable: GearCity's *marque* is the cleanest shipped precedent — an acquired brand that "do[es] not operate independently from the company" yet keeps its own reputation lane and a full disposal menu (spin-off/sell/discontinue/restore) (05-comparators-A.md F19-20; 00-KEY-FINDINGS.md:401, 715). Model D is the shipped norm in both a comparator (Capitalism Lab's one-click `[Acquire]` vs `[Acquire and Merge]`; Software Inc.'s `Takeover` vs `Subsidiary`) and in every real-world case reviewed — DreamWorks/Soros keeps a separate library-vs-studio-vs-distribution split, Disney/Fox absorbs operations and retains "20th Century Studios" as a label, and *no* real case ships an indefinitely-autonomous acquired studio the way Model B would require (08-realworld-ma.md design implications; 00-KEY-FINDINGS.md:406, 642).

| Criterion | A Full Absorption | B Autonomous Subsidiary | C Absorb+Retain Label | D Owner Choice (A or C at close) |
|---|---|---|---|---|
| Player comprehension | High (one outcome) | Low — MGT2/Software Inc./Capitalism Lab community verdict: confusing, tedious | High (GearCity marque is the clean precedent) | Highest — Capitalism Lab's one-click fork is the shipped comparator |
| Historical identity | Preserved via dated relation | Preserved but reads as a second business | Preserved and visible (label survives) | Preserved either way, player chooses visibility |
| Management burden | LOW once H5 ships | HIGH, unconditional and structural | LOW once H5 ships | LOW once H5 ships (menu excludes B) |
| Gameplay value | Adequate | Comparator-attested "fiction"/tedium once novelty fades | High — asset-sale/spin-off surface (GearCity) | Highest — player gets the choice comparators show players want |
| AI/rival compatibility | HIGH once H5 ships | Fails unconditionally (H5 never applies) | HIGH once H5 ships | HIGH once H5 ships |
| Save/performance | Bounded (terminal state stops growth) | Unbounded — compounds an already-exceeded budget | Bounded | Bounded |

**Recommendation (inference, R12).** Model D — Owner Choice between Absorb Completely and Absorb Operations + Retain Brand as Label, decided once at transaction close — dominates or ties on every criterion and is the only model that structurally excludes Model B's two unconditional failure modes (its menu simply never offers B). This is a demonstrated conclusion against the assignment's own named criteria, not an assertion. **Prerequisite:** shipping any of A/C/D requires a terminal `RivalBusiness` state honored by both the tick loop and the save validator (H5) — this is a blocking dependency tied to whether/when P15B's closure-settlement lifecycle is authorized (§20).

## 6. Exact acquisition transfer bundle (assignment §2.F, eight questions)

**Q1 — Does acquired cash become buyer cash?** Yes, at par. GearCity transfers "cash funds" as part of the marque bundle (00-KEY-FINDINGS.md:400); real cases (Amazon/MGM, MGT2 debate aside) generally price net-of-cash with cash following the entity. Mechanically: one new typed `LedgerKind` (acquisition-class, e.g. `acquisitionCashIn`) on the buyer side and one new `RivalMoneyKind` on the rival-target side, both correlated by one `CorporateEventId` (03-authority-domains.md F "Cash transfer"; 00-KEY-FINDINGS.md:70, 103, 217).

**Q2 — Does debt transfer?** **There is no debt instrument to transfer.** No loan/credit/investor/interest object exists in accepted code or approved P11 scope; player financing and bankruptcy remain explicitly Owner-blocked (P11-REQ-041/042; 00-KEY-FINDINGS.md:69, 151). "DEBT/LIABILITIES" in the transfer bundle must therefore mean **existing typed obligations only**: remaining guaranteed-contract balances, committed production costs, scheduled Opex. These already transfer with the people/projects that carry them (§ below). A true debt instrument is a separate, future P11 Owner gate and must not be invented inside P16 to satisfy this question. This is the report's first flagged structural collision (§ Structural Problems, below).

**Q3 — Do employee contracts transfer intact?** Yes, as a **new P12 employer-transition row**, never in-place re-owning — `contractId` is minted by P12 code and embeds the employer StudioId (`<studioId>:contract:<talentId>:<week>[...]`), so a contract literally cannot change employer without becoming invalid under the existing validator (04-code-audit.md F; 00-KEY-FINDINGS.md:210, 223). The transfer is: end the target-employer `IndustryEmployment` row, mint a new row under the buyer with **identical terms**, a new reason code (`assumed`), and one `fromStudioId→toStudioId` receipt; copy `Contract.signingBonus` into the buyer's `state.contracts` **without re-debiting** it (an explicit invariant is needed to prevent double-charging). P12's own design authority already names "sale/assignment" as a lawful terminator of exclusive contracts (§22; 00-KEY-FINDINGS.md:157), so this reuses a pre-existing legal category rather than inventing one.

**Q4 — Can the player release inherited staff afterward under ordinary termination law?** Yes — no special rule needed. Ordinary P10/P14 termination law applies unchanged: `terminationCost = round(0.5 × guaranteedComp)`, refused while the person is mid-task on an active screenplay (employment.ts:172-180; 00-KEY-FINDINGS.md:89, 224). This 50%-of-remaining-guarantee cost is the natural, non-arbitrary integration cost for a post-acquisition roster trim — no new punitive multiplier is needed or recommended.

**Q5 — What happens to active movies?** They transfer and finish under the buyer as a **re-formed Production** preserving `productionId`/`conceptId`/participants/remaining-ticks, with a ledger witness row at the closing week. Rival productions are, mechanically, easier to re-parent than a player-crossing case because both sides share identical Production/ScriptDevelopment shapes, one shared employment array, and rival facilities are always `requiresSetBinding=false` with no placement-ledger entanglement (16-gap-rival-ai-acquisition-code-feasibility.md F; 00-KEY-FINDINGS.md:804-805). The buyer may choose continue-or-cancel (at a defined write-off cost, per Fox/Disney's $170M inherited-slate loss precedent; 00-KEY-FINDINGS.md:643); bankruptcy-path active productions are instead separate auction lots per Real-World Lesson §15.

**Q6 — What happens to target facilities if only one lot is actively managed?** **Automatic liquidation at closing**, using the existing depreciated-demolition-credit law verbatim: `round(currentBlueprintCapex × 0.5)` for facilities, `× 0.35` for Sets, an invariant-enforced fraction strictly `<1` (tuning.ts:1598-1613; placement.ts:1025-1028; 00-KEY-FINDINGS.md:75, 219). Buildings never teleport to the buyer's lot; this satisfies §2.G directly. Note the smallest-correction flag: for **rival** targets today this is nearly moot, because rivals hold only four abstract, once-paid capacity rows with no blueprint/tier/footprint (00-KEY-FINDINGS.md:77, 164, 227) — see Structural Problems §5.

**Q7 — What exactly does acquired research grant?** Knowledge, not installation. The buyer gains a `TechnologyAdoption` row at `readyToAdopt` citing the target's provenance/adoption ID (per-studio keyed by `(StudioId, TechnologyId)`; 00-KEY-FINDINGS.md:81). The buyer must still lawfully install/build/convert the physical facility under ordinary P09/P13 law — cash accelerates qualified research, it never bypasses facility capability or necessary construction work (Owner Rulings §2.4.1/§2.4.3; 00-KEY-FINDINGS.md:159). **In-flight research does not transfer**: P13-OD-06 states work "never moves across technologies or studios" (00-KEY-FINDINGS.md:83); absorbing it requires either accepting the loss (typed disposition, e.g. `cancelled_with_receipt`) or an explicit Owner-granted one-time successor exception — this is not silently overridden.

**Q8 — What happens when the target has a higher physical facility tier than the buyer?** The buyer gains only the **eligibility** to build/convert to that tier for a capability it already knows about via Q7's adoption row; the physical upgrade must still be lawfully installed under existing P09/P13 conversion law (structure/space/access/compatibility descriptors). No teleport, ever. For rival targets this question is presently moot in the strict sense — rivals have no per-facility tier field today (04-code-audit.md F; 00-KEY-FINDINGS.md:227) — a smallest-correction flag, not a design failure (Structural Problems §5).

## 7. Physical property

Rivals own no buildings or lot today — `rivalStartingFacilities` returns four abstract capacity rows and validation requires "capacity acquisition not paid exactly once" (03-authority-domains.md; 00-KEY-FINDINGS.md:77, 164). This makes assignment §2.G's hardest alternatives (transferable equipment, remote-lot system) moot for the *current* rival substrate: **Recommendation** is Option 1 (automatic liquidation at closing, existing credit fractions) plus Option 3 as the durable framing for anything that isn't liquidated (remote corporate property, if it ever exists, is a financial-asset line only, never a second managed lot). Option 4 (transferable equipment) is explicitly deferred until a `ConversionRequirementDescriptor.installedEquipment` field exists to make "equipment" a distinct object from "installation" (00-KEY-FINDINGS.md:107, 179). No comparator ever made buildings or lots the prize of an acquisition — Story Properties, library rights, and knowledge were always the target (05-comparators-A.md design implications; 00-KEY-FINDINGS.md:357).

## 8. Active productions

Covered mechanically in §6 Q5. Governing distinction: **healthy acquisition** transfers active productions to finish under the buyer (buyer chooses continue/cancel); **bankruptcy/estate disposition** treats each active production as its own lot with its own reserve, exactly as Orion's ~10 frozen completed films, Relativity's held-up unreleased titles, and TWC's per-film disposition all show in reality (08-realworld-ma.md design implications; 00-KEY-FINDINGS.md:645). No "transition owner" state beyond "in estate, unsold" is needed. Production/script identity is preserved exactly (`productionId`, `conceptId`); no duplicate identity is ever created — re-formation on the buyer's lot reuses the existing IDs and appends a transfer-correlated ledger row rather than minting new identity, satisfying the assignment's "no duplicate film/project identity" instruction.

## 9. Historical identity/status model (the three §2.I examples)

**Finding base.** `StudioIdentity` has exactly ten exact-key fields and **no status/dormant/closed/acquired/successor field at all** (hollywoodTypes.ts:6-17; 00-KEY-FINDINGS.md:145, 213). P12 design authority already states the needed distinction in prose: "Closure releases or resolves talent under contract law ... freezes the studio profile as historical ... Acquired is a later distinct outcome, never an alias for closed" (§30; 00-KEY-FINDINGS.md:149). The registry itself is fixed at ten identities with no allocator for more (00-KEY-FINDINGS.md:146, 215).

**Recommendation (inference).** Corporate status is an **additive root of dated events keyed by the exact, never-reminted `StudioId`** — never a field mutation on `StudioIdentity`, and never a second registry:
- **CLOSED** (P15 settlement, no successor) — RKO/Orion-style; identity remains permanently searchable, filmography/credits/awards/Standing-peaks/ownership-history remain queryable forever.
- **ACQUIRED** (P16 transaction, successor = buyer, brand *may* be retained per Model D's choice) — Warner-Brothers-style example in the assignment.
- **ABSORBED/MERGED** (same P16 transaction type, brand *not* retained) — United-Artists-style example.

`acquired ≠ closed` is already fixed as accepted design law (HIS-013; 00-KEY-FINDINGS.md:140, 149); the exact enum values are recon, but the three-way split maps directly onto the assignment's three worked examples. **This entire model is gated on the same H5 terminal-business-state prerequisite as §5** — see Structural Problems §3.

## 10. Rival M&A

Settled law already establishes symmetric transaction law with an explicitly asymmetric *terminal-eligibility* backdrop: the player has a no-hard-bankruptcy ruling that does **not** extend to rivals — rivals may legitimately fail, be sold, merged, or acquired under the same transaction law (OWNER-RULINGS-HOLLYWOOD-HORIZON.md §3-4; 00-KEY-FINDINGS.md:148). "No isPlayer multiplier or exemption" is explicit P15 law (00-KEY-FINDINGS.md:153). Recommendation: rivals bid under **identical** valuation/eligibility/premium law as the player (R30), using a new derived RNG purpose (`ownership-v1`) keyed on `(bidder, target, roundOrdinal)` — never the calendar, never `state.rngState` — following the codebase's own established additive-purpose pattern (04-code-audit.md; 16-gap-rival-ai-acquisition-code-feasibility.md; 00-KEY-FINDINGS.md:230, 800). One genuinely new architectural fact: **no existing rival decision function ever reads another business's data** — an AI bid-eligibility check is the *first* cross-business state read in the engine and must be explicitly charter-authorized, kept separate from the player-facing privacy projection in `bridge/industry.ts` (16-gap...md F; 00-KEY-FINDINGS.md:801, 810). Frequency/eligibility governors: affordability (post-close reserve requirement), a size-scaled cooldown after any founding/entry, the ≥3-active-rival floor as a hard refusal predicate (see Structural Problems §8), and no player-only surcharge to "fix" exploits (GearCity did this and it violates the symmetric-law rule; 00-KEY-FINDINGS.md:399, 424).

## 11. Asset sales & exploit guards

Owner wants individual Story Property / film-rights / corporate-asset sales (§2.D, §2.K). The original already shipped the load-bearing anti-flip primitives to reuse: the Star & Script Selling Facility's **eight-year tenure vesting** to full value and its **age-55 decline curve** (Prima pp.8,21,61; 00-KEY-FINDINGS.md:15) — transpose both onto Story Property/library-rights resale as (a) a rising-fraction holding-period discount for N years post-acquisition, and (b) a remaining-exploitation-value curve. Exploit guards, all grounded in evidence rather than invented: **(1)** single-holder + append-only ownership log with a validator refusing any transfer whose `from ≠ current holder` (chain-of-title precedent; 00-KEY-FINDINGS.md:270); **(2)** rights-in-use lock — no R1 sale or exclusive R3 grant while an active production/`TheatricalRun` sits on the property, unless the production transfers with it or a licence is explicitly retained (encumbered sales carry live licences, per Sony/Marvel and DreamWorks/Paramount precedent; 00-KEY-FINDINGS.md:274, 630); **(3)** a strict `<1` recovery-fraction invariant reused from the existing demolition-credit idiom, so sale value is always below acquisition/creation cost absent a genuine competing-bid receipt (00-KEY-FINDINGS.md:113, 219, 243); **(4)** AI deal-memory (bid ≤ received price × (1−haircut); ask ≥ paid price × (1+premium) for a bounded window) to stop buy-cheap-sell-back loops, the exact failure mode Software Inc.'s own developer admitted ("the calculation for deciding IP price was placeholder"; 00-KEY-FINDINGS.md:278); **(5)** a valuation floor with cash conservation on the AI side. No comparator or real case needed territory/window sub-splits to make these guards work.

## 12. Healthy-studio acquisition (willingness/price, what the player sees)

**Finding base.** Every disciplined comparator that ships this mechanic shows willingness as a **visible, typed stance with a genuine refusal right**, not a hidden multiplier: GearCity's shareholder vote is health-driven and a healthy target simply refuses (00-KEY-FINDINGS.md:397); TEW 2020's takeover acceptance depends on consecutive negative-balance months, owner personality, and relationship, with an explicit refusal right (00-KEY-FINDINGS.md:349); Football Manager shows a typed stance (Desperate/Keen/Curious), a shown value, interested-party reasons, and time-limited tags (00-KEY-FINDINGS.md:475); Big Ambitions shows a stated valuation with typed drivers and a refusal right (00-KEY-FINDINGS.md:479). The counter-examples are damning: Capitalism Lab's opaque share-accumulation is the developer's own deliberate anti-pattern to preserve difficulty (00-KEY-FINDINGS.md:407); Startup Company's no-refusal/no-premium model produces the feared complete-monopoly end state (00-KEY-FINDINGS.md:480). Real M&A confirms boards refuse regardless of price (Disney rejected Comcast's 2004 bid "as too low") or accept a lower bid for certainty (Fox chose Disney over a higher Comcast offer on regulatory-risk grounds) — price influences but never compels (08-realworld-ma.md; 00-KEY-FINDINGS.md:635).

**Recommendation (inference).** A published **Willingness State** (`NotForSale | Reluctant | Open | Willing`), driven by visible, non-hidden inputs (recent performance/Standing trend, a P15 condition fact if distressed, an "independence preference" flag), each with a stated reason. Price = Enterprise Valuation (§14) × an **independence-premium band** (not a "control premium" — see the terminology correction in §16) keyed to the Willingness State, published as one versioned formula so UI copy is derived from the same law rather than drifting from it (GearCity's own prose/code drift is the cautionary tale here; 00-KEY-FINDINGS.md:423). A refused offer is always accompanied by a typed reason and starts a cooldown before the next offer is legal (`nextOfferAllowedWeek`) — this satisfies the assignment's explicit "no opaque bargaining simulator" and "target can refuse" requirements simultaneously.

## 13. Bankruptcy auction/acquisition (§2.M, five alternatives)

**This section carries the report's most serious structural collision — see Structural Problems §2 for the full statement.** In short: no P15 document contains the word "auction" or "liquidation," and P15's closure-settlement is written to **cancel or settle every category, leaving no transferable estate** (11-gap-p15-closure...md; 00-KEY-FINDINGS.md:831). The assignment's premise that "P15 may decide a rival becomes bankrupt and its assets enter auction" therefore describes a step no current document defines — P16 must supply it explicitly, not assume it exists.

**Recommendation (inference), gated on the smallest correction below.** Alternative **5 (Hybrid)** is recommended, matching both the real-world pattern (§363 sales default to whole-lot-below-book with contract cherry-picking; TWC $310M cash + assumption of up to $127.5M in liabilities; 00-KEY-FINDINGS.md:622, 634) and the comparator pattern (GearCity's creditor-sale-with-explicit-assumed-debt is the only comparator with a live "auction" concept and it is not a multi-round bidding war; 00-KEY-FINDINGS.md:402). Concretely: **Alternative 4 (Assumption Purchase)** for whole-studio deals — buyer pays a lower price but assumes the target's *existing typed obligations* (never a fabricated debt instrument, per §6 Q2) — and **Alternative 3 (Clean Asset Purchase)** for per-property/per-film lots when no whole-studio buyer appears, exactly mirroring Carolco's library going to a rival bidder while the Terminator continuation rights were auctioned as a *separate* lot (00-KEY-FINDINGS.md:623). A live, multi-round competitive auction (Alternative 2 as commonly imagined) is **not recommended for v1**: no comparator in the entire research program ships a genuine competitive-bid auction for distressed assets (05-comparators-A.md; 00-KEY-FINDINGS.md:417), and a sealed one-shot comparison among eligible rival bidders is sufficient to satisfy §2.J's "rivals bidding at auction" anti-snowball lever without the engineering cost of a bidding-round state machine.

## 14. Book Net Worth vs Enterprise Valuation vs Transaction/Auction Price

**Finding base.** Standard finance doctrine is unambiguous and directly answers the Owner's "verify" instruction: book value ≠ liquidation value; expected value = max(status-quo, orderly-liquidation) (Damodaran; 00-KEY-FINDINGS.md:555); enterprise value nets cash/non-operating assets and never double-counts intangibles inside both cash flows and the balance sheet (Damodaran "tangled web of values"; 00-KEY-FINDINGS.md:553). Amazon's own 10-Q for the MGM deal is the cleanest real proof of the separation the Owner asked to verify: of an $8.45B headline, $3.4B was allocated to video content and $4.9B to goodwill — library value and brand/strategic value are **separate lines**, and the premium is applied once to the total (00-KEY-FINDINGS.md:620, 649). Shipped comparators that keep these numbers separate (GearCity's Price Evaluation / market cap / Takeover Price; OpenTTD's three distinct formulas; Capitalism 2's Net Worth beside Market Value) are the ones players call transparent; comparators that collapse them into one blended number (Software Inc.'s "company worth," patched repeatedly, resetting to zero on takeover) produce documented confusion (00-KEY-FINDINGS.md:398, 414, 467, 560).

**Recommendation (inference).** Four numbers, never collapsed, each a versioned read-model row, never a P11 ledger fact:
1. **Book Net Worth (BNW)** — an accounting identity computable *today* from existing P11 rows: cash + scheduled receivables + tangible at existing recoverable-demolition-credit − any existing debt instrument (none exists yet). Committed payroll and production cost are shown **beside**, never subtracted, per P11 law (00-KEY-FINDINGS.md:572).
2. **Studio/Enterprise Valuation (SV)** = `max(going-concern basis, asset basis)`, where going-concern = capitalized trailing operating surplus + cash + receivables + Story Properties/library (historical/strategic weight only, per §4) + recoverable production work, and asset basis substitutes tangible-at-recoverable-credit for the capitalized-surplus term. The `max()` is the specific rule that closes the "buy cash-back tangible below its recoverable value" arbitrage (09-valuation-finance.md Scenario D; 00-KEY-FINDINGS.md:567).
3. **Transaction/Offer Price** = SV × independence-premium band (healthy path, §12) or an assumption-purchase price (distressed path, §13).
4. **Auction/Clearing Price** = the outcome of the distressed disposition process (§13), bounded below by a liquidation reserve, never inferred from book value alone.

**Terminology correction (inference):** rename the assignment's "control premium" to **independence premium** throughout P16 prose. Damodaran's actual "value of control" is a *buyer-side* concept (optimal-minus-status-quo value, larger for *poorly*-run firms) and explicitly rejects any rule-of-thumb percentage (00-KEY-FINDINGS.md:556); what a healthy-target premium actually prices in a one-lot-absorber game is the **seller's reluctance to sell at all**, which is a different and simpler thing to model. This also resolves the Owner's own "verify" question in §2.N as **YES**: healthy acquisitions should begin from Enterprise Valuation + independence premium, while distressed price should emerge from bids/reserve around liquidation/strategic value — this is corroborated independently by OpenTTD's three-formula design, GearCity's health-driven premium, and Damodaran's own doctrine (00-KEY-FINDINGS.md:566).

## 15. Real-world lessons

Four load-bearing lessons, each already folded into the rules above: **(1)** rights genuinely decompose into exactly the four kinds recommended in §3 across every case reviewed — Disney/Pixar (film ownership separate from the creative studio), Sony/Marvel (activity-conditioned reversion), Lucas/Fox (perpetual per-film distribution right coexisting with returned continuation rights), DreamWorks/Soros/Paramount (library, distribution, and continuation each held by different parties at once) — no case ever needed a territory or media sub-split (00-KEY-FINDINGS.md:616-621, 630, 639). **(2)** Model D (absorb operations, retain a non-operating label) is the observed real norm, and retained labels have a documented *half-life*, not permanence: Lorimar (5 years), Marvel Entertainment (14 years), MGM as a distinct entity after the 1986 Turner split (~18 months) — this argues against ever presenting a retained label as a durable second business (00-KEY-FINDINGS.md:642, 633). **(3)** healthy-deal premiums cluster 20–40% and rise with a genuine rival bidder; boards can and do refuse regardless of price (00-KEY-FINDINGS.md:635). **(4)** distressed sales are inherently hybrid, use a stalking-horse floor that can move (TWC's price was cut from $310M to $289M with no competing bids, then Carolco's library saw a rival raise the price from $47.5M to $58M) — both directions are realistic and neither needs a live bidding-round engine to be represented (00-KEY-FINDINGS.md:622-623). **(5)** facilities/lots never teleport in any case reviewed — the Fox lot, the RKO lot, and the MGM Culver City lot were each sold or retained separately from the ownership transaction (00-KEY-FINDINGS.md:643).

## 16. Comparator lessons

Nine tycoon/management titles plus two board games were reviewed. The single most load-bearing negative lesson: **any transferable asset that gates exclusive access to a shared audience/market channel snowballs without bound** — Hollywood Animal's purchasable cinemas became "basically the meta," destroying rivals' ability to compete, and the developer's only fix was a scripted decree stripping theaters from everyone (00-KEY-FINDINGS.md:336, 352, 358). This is directly checked against Project: Studio's own market design in §17. The second load-bearing lesson: **partial ownership/equity stakes are an exploit magnet in every system that shipped them** — OpenTTD removed share trading entirely in 2024 calling it "generate infinite money ... ABSOLUTELY NOTHING" for player decisions (00-KEY-FINDINGS.md:464); Blockbuster Inc.'s passive dividend stakes were disabled because "the game was too easy" (00-KEY-FINDINGS.md:348); GearCity's own flip exploits ("about 7 billion $ from just buying and selling companies") required repeated patches (00-KEY-FINDINGS.md:404). This grounds R34 below. Third: **rights need a "rights-in-use" concept and an origin split (owned vs licensed), and nothing more** — Mad Games Tycoon 2's IP system (single-use license, genre-fit modifier, era-scaled price, cannot trade an IP while a product using it is on sale) is the smallest working shape observed and directly informs the R1–R4 bundle in §3 (00-KEY-FINDINGS.md:277, 344). Fourth: **inherited operations are a burden, not a reward** — Offworld Trading Company's designer explicitly documents that all-or-nothing buyouts left players managing buildings across the map "they didn't have time to manage," confirming the Owner's single-lot preference from the player-experience side, not just the engineering side (00-KEY-FINDINGS.md:471).

## 17. Anti-snowball

**Finding base — direct check against the assignment's own "Hollywood Animal" example.** Accepted code and approved P15A design were checked specifically for an HA-cinema-style ownable, capacity-limited, exclusive-access channel (12-gap-...concentration-check.md; 00-KEY-FINDINGS.md:767-777). Result: **none exists.** `competitionFactor` is hardcoded to `1.0` and `MarketState.competingSlate` is empty at world generation — there is no cross-studio market-share variable to concentrate at all (00-KEY-FINDINGS.md:771). P15A's own recommended shared-market mechanic (genre/release-window "saturation pressure") is a **symmetric negative externality that degrades every crowding release including the releaser's own** — nothing is purchased to gain access to it, so it cannot be cornered the way HA's cinemas were (00-KEY-FINDINGS.md:772). Most strikingly, "screen/exhibition capacity" — the *literal* analogue to HA's cinemas — was already named by P15A's own Owner-decision table and **explicitly excluded from approved scope**, citing "avoids fake precision and a second scarce-resource model" (00-KEY-FINDINGS.md:773). This is independent verification, not inference: the exact mechanism the assignment worries about was considered by name and deliberately deferred before this research program ever started.

The one genuinely live concentration risk found is different from the assignment's framing: the **fixed, non-replenishing 60-person talent pool under strict one-employer exclusivity** is a real capacity-limited, contested resource (00-KEY-FINDINGS.md:774). Whether a serial acquirer can concentrate a growing share of it depends entirely on the still-open Owner question in §6 Q3 (do inherited contracts transfer intact) — if yes, a slower, partial, labor-market cousin of HA's snowball becomes possible (00-KEY-FINDINGS.md:775). **Smallest correction (R31 below):** bind an acquirer's assumed headcount to its own usable production/development capacity — mirroring existing rival-AI staffing discipline, which already only staffs to fill one active production and never accumulates idle contracts (hollywoodTick.ts:146; 00-KEY-FINDINGS.md:777) — and require any inherited contracts beyond that capacity to settle under ordinary termination law within a bounded integration window, rather than being held indefinitely.

Beyond that check, the assignment's other three example resources (fixed weekly release-slot count, a capped marketing/publicity pool, a fixed per-category awards-nomination count) **do not exist in accepted code or approved law at all** — Awards/nominations have no root whatsoever, and no theatrical-date/screen-inventory calendar exists (00-KEY-FINDINGS.md:776). No corrective action is needed for resources that were never built.

**Minimum necessary anti-snowball set (inference, R31):** independence-premium cost (§12) + inherited-obligation integration cost (§6 Q2/Q3, real not fabricated) + ordinary-termination cost for redundant staff (§6 Q4) + capacity-bound contract assumption (this section) + a per-target cooldown after any completed or rejected deal + the already-existing **≥3-active-rival floor** treated as a hard eligibility predicate (Structural Problems §8). No artificial M&A cap, antitrust mechanic, or hidden catch-up subsidy is recommended — every comparator and every piece of anti-snowball literature reviewed (Sirlin; Thoughtful Gamer) prefers integrated friction and visible escalating cost over caps or hidden rubber-banding (00-KEY-FINDINGS.md:485, 494).

## Paper scenarios A–F

All figures are PAPER HYPOTHESES for illustration only; no number here is a proposed tuning constant.

**Scenario A — Bankrupt small studio.** Weak cash (−$40k), one modest Story Property (2 released films, no sequel heat), 6 employees under guarantee (avg. 40 remaining weeks each), no valuable technology. Book Net Worth ≈ tangible-recoverable-credit ($120k facilities × 0.5 = $60k) + cash (−$40k) = **$20k**. Going-concern SV is near zero (no meaningful trailing surplus). Under R28, this is a **clean asset purchase** case: the whole-company lot has no going-concern premium worth paying, so per-property/per-contract lots (Story Property, a couple of assumable contracts at cure) clear near the asset-basis floor. Whole-company purchase would only make sense if a bidder specifically wants the StudioId's historical continuity for a label — otherwise asset liquidation dominates, exactly as OpenTTD's bankruptcy ladder and TWC's §363 default outcome (no competing bidder) both show.

**Scenario B — Valuable distressed studio.** Heavy negative cash (−$300k), a valuable 12-film library with two recognizable Story Properties, excellent adopted technology (2 tiers ahead of the field), 3 active productions. Book Net Worth is low or negative (debt-like obligations dominate tangible credit). Enterprise Valuation is high (library + property + technology-eligibility strategic weight, capitalized surplus from strong past releases). Auction/clearing price, per R28, is bounded by a liquidation reserve on the low end and by rival bidders' private valuations of the *specific* library/technology combination on the high end — these three numbers (BNW, SV, clearing price) are necessarily far apart, which is the entire point of §14's separation: a buyer paying near SV for the library+technology combination while BNW alone would suggest the studio is worthless is not a contradiction, it is the model working correctly.

**Scenario C — Healthy rival.** Profitable, strong Standing, two valuable Story Properties, explicit independence preference (Willingness State = `Reluctant`). SV = $9,700k (paper). Buyer's rational "parts value" if it liquidated everything post-purchase is structurally lower (paper $6,864k, per 09-valuation-finance.md Scenario C; 00-KEY-FINDINGS.md:566) — this gap **is** the independence premium in a one-lot-absorber design: since the buyer cannot run the target as a second operation, it can only rationally pay up to (parts value + strategic increment), and the seller's `Reluctant` state pushes the ask toward the top of the published band. If the offer is below the band, the target refuses with a typed reason and a cooldown starts.

**Scenario D — Technology target.** Player targets a studio purely for research it lacks (2 tiers ahead). Per §6 Q7, the transaction grants the buyer a `TechnologyAdoption` row at `readyToAdopt` — **no facility magically appears.** The buyer's post-close obligation list gains "install/convert Tier III facility" as ordinary P09/P13 work; the transaction's independence premium is paid regardless of whether the buyer ever finishes that installation. This verifies the Owner's stated principle exactly as instructed: knowledge transfers, installation does not, and the paper arithmetic shows the buyer cannot arbitrage the difference (SV's `max()` rule already prices tangible/strategic value independently of whether the buyer intends to build anything).

**Scenario E — Serial acquirer.** Player buys three studios over ten years (≈520 weeks). Snowball/exploit check against R31: (1) each deal pays an independence premium and inherits obligations — no free lunch; (2) if inherited contracts transfer intact (§6 Q3, open decision), the capacity-bound assumption rule caps how much of the 60-person pool any single acquirer can actually hold onto post-integration, forcing excess back into ordinary termination/free-agency within the integration window; (3) each deal reduces the active-rival count toward the ≥3 floor — a serial acquirer's *third* purchase is the one most likely to trip the eligibility predicate and be refused outright (Structural Problems §8), which is the single most important number in this scenario and is **already law**, not a new invention; (4) a per-target cooldown and the strict `<1` anti-flip invariant prevent the acquirer from using acquired assets as a buy-low-sell-high cash engine. Net: the serial acquirer accumulates library/property/technology value (a legitimate strategic snowball, matching every real-world case reviewed) but cannot accumulate an unbounded talent monopoly or an unbounded rival-count reduction without hitting an explicit, typed refusal.

**Scenario F — Rival acquires rival.** Symmetric transaction law (R30) applies without modification. Mechanically, this case is **easier**, not merely symmetric, because both sides already share identical `RivalBusiness`/`Production`/`ScriptDevelopment` container shapes and neither side has a placement-ledger/set-binding entanglement to reconcile (16-gap-...md; 00-KEY-FINDINGS.md:797, 805) — the "hardest constraint" identified for player-crossing productions (a placed-facility greenlight-ledger evidence invariant) cannot arise in a pure rival-to-rival transfer. History preservation is identical to the player case: the target's `StudioId` persists forever with a dated `ACQUIRED`/`ABSORBED` event, credits/filmography never rewrite to the acquirer, and the acquirer's own identity and history are equally unaffected by the direction of the transaction — there is no code path in which "the AI did it" produces a different historical-integrity outcome than "the player did it."

## Structural problems (Owner-selected rules creating collisions) — exact statement + smallest correction

1. **No debt instrument exists; player financing is Owner-prohibited** (P11-REQ-041/042 OWNER-BLOCKED; 00-KEY-FINDINGS.md:69, 151), yet §2.F Q2 and §2.O both presuppose "debt" as a transferable/financing concept. *Smallest correction:* the transfer bundle's "DEBT/LIABILITIES" category means **existing typed obligations only** (contract guarantees, committed production costs, scheduled Opex); a genuine debt instrument remains a separate, not-yet-authorized P11 Owner gate and must never be fabricated inside P16 to answer this question (R19).

2. **P15 closure-settlement, as approved, cancels or settles every category and leaves no transferable estate** — the word "auction" appears in zero P15 documents (00-KEY-FINDINGS.md:160, 831) — yet §2.M presupposes that "P15 may decide a rival becomes bankrupt and its assets enter auction." *Smallest correction:* insert one new pre-settlement gate — a closure-settlement request first checks for an existing, already-cleared P16 acquisition transaction at the frozen source `GameState` revision; if found, each owner's disposition becomes `assign-to-acquirer` instead of cancel/release/settle, using one new typed disposition value inside the existing per-owner settlement machinery (§12.3). This requires no new estate-holding root and does not reopen the settlement invariants themselves (R28, R09).

3. **`StudioIdentity` has no status field, and every entered rival's business ticks unconditionally forever** (`hollywoodValidation.ts:331`'s strict bijection + `hollywoodTick.ts:221-288`'s unconditional loop; 00-KEY-FINDINGS.md:213-214, 714, 836-837) — there is no way to represent "operations ended" today, which blocks Models A, C, and D equally (not just an acquisition-specific gap). *Smallest correction:* an additive terminal-business-state ("H5") honored by both the validator and the tick loop, landing on the already-distinct `acquired` label rather than `closed` — this is a blocking prerequisite that should be explicitly named as shared infrastructure for P15B and P16C rather than built twice (R12, R14).

4. **`contractId` embeds the employer StudioId and `scriptProjectId` is bound to the owning studio's array index** (00-KEY-FINDINGS.md:210, 209) — neither can be literally "moved" to a new owner without becoming invalid. *Smallest correction:* transfer always means mint-new-row-under-buyer-with-identical-terms-and-a-new-reason-code, never in-place re-owning; a transferred `scriptProjectId` is re-minted in the receiver's own namespace with a provenance pointer back to the original (R20).

5. **Rival facilities are four abstract, once-paid capacity rows with no tier/footprint/blueprint history** (00-KEY-FINDINGS.md:77, 164, 227) — §2.F Q8 ("target has a higher physical facility upgrade") and §2.G's building-liquidation alternatives presuppose a physical referent that does not exist for rival targets today. *Smallest correction:* write the rule generally (buyer gains eligibility, must still build) so it is correct and non-trivial the moment rival facilities gain tiers, but explicitly document that it is **currently a near-no-op** for rival targets rather than silently implying parity that doesn't exist (§6 Q6/Q8).

6. **The library has zero cash flow today** (`TheatricalRun` locked at completion, no further revenue; 00-KEY-FINDINGS.md:95, 220) while assignment §2.C frames library value as something that "contributes to" valuation and other systems. *Smallest correction:* Library Value is strictly a valuation-lane input (§4, §14), never a P11 cash fact, until a P18 distribution channel exists — already the assignment's own instruction, restated here as a hard boundary rule (R06).

7. **Rival cash/obligations/budgets/forecasts are hidden by default** (visibility doctrine; 00-KEY-FINDINGS.md:73, 155) yet §2.L/§2.N require the player to see enough to evaluate a healthy-acquisition offer. *Smallest correction:* define an explicit due-diligence disclosure receipt — a new "PUBLIC AFTER [transaction phase]" event — rather than reading hidden fields directly from `RivalAccount`/policy/forecast state in any player-facing projection (R29).

8. **The fixed ten-identity registry and the ≥3-active-rival floor are hard, already-approved constraints** (00-KEY-FINDINGS.md:146, 165) that a serial-acquisition system can silently violate by absorbing rivals down below the floor with no replacement-entrant mechanism authorized. *Smallest correction:* treat the floor as an explicit transaction-eligibility predicate — any acquisition that would drop active rivals below 3 is refused with a typed reason — until and unless a separate P15B replacement-entrant slice is authorized (R17, R31).
