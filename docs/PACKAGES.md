## Glossary

- **Owner** — the product authority who issues product rulings and accepts or rejects an exact player-facing candidate.
- **Current Ops** — the current execution/integration coordinator operating within Owner law; may issue a bounded order and decide how a reviewed repair lands.
- **Future Ops** — research and planning function. Its packages are advisory until Current Ops reconciliation and an explicit execution order.
- **technical KEEP** — a technically evidenced checkpoint worth preserving. It is not Owner acceptance, whole-package completion, or campaign integration.
- **Owner acceptance** — an explicit Owner ruling on an exact candidate and evidence identity. It cannot be inferred from tests, review, branch names, or a prior technical KEEP.
- **WIP** — mutable, unsealed work in progress. A WIP ref is forward evidence and a discovery pointer, not accepted authority or edit permission.
- **pre-readiness** — planning, code reconnaissance, dependency mapping, and decision exposure before an implementation gate. It grants no implementation authority.
- **Standing** — the separate TypeScript-owned channels Audience Awareness, Industry Prestige, and Commercial Confidence. It is not one overall score, Power Ranking, cash, or legacy.
- **Hollywood Wire** — a downstream narrative consumer of public typed receipts. It may select and render stories; it creates no simulation fact, award, result, visibility escalation, or history.
- **old campaign labels** — legacy `M*`, `D-*`, `CP*`, test-arm names, and similar historical identifiers. They locate evidence within their original campaign only.
- **P-number labels** — the product package sequence P04–P18. A historical test arm or campaign checkpoint containing text such as `P16` is not automatically Package 16.

## Cross-branch retrieval

Do not switch an active checkout. In a separate owned clone or disposable worktree:

```bash
git ls-remote REPOSITORY_URL refs/heads/DISCOVERY_BRANCH
git -C /absolute/path/to/owned-clone fetch --no-tags origin IMMUTABLE_COMMIT
git -C /absolute/path/to/owned-clone cat-file -e 'IMMUTABLE_COMMIT^{commit}'
git -C /absolute/path/to/owned-clone show 'IMMUTABLE_COMMIT:DOCUMENT_PATH'
```

Verify the repository locator before fetching. Use the full commit from this index rather than assuming the branch still points to it. Private Unity retrieval requires explicit repository access; if unavailable, record `NOT VERIFIABLE — PRIVATE SOURCE ACCESS REQUIRED` instead of a pass.
