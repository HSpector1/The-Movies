V3 remains immutable and hash-verified. The complete patch targets the exact installed-v2 preimages recorded in the manifest; V3-TO-V4.patch isolates the two finding corrections. No runtime, compiler, test or checkout changes occurred. The separate test author owns the two controls in the existing positive leaf. **Known native issuer.** takeSubjectOwner checks the exact native production history before either seller-continuation or ordinary rival/player fallback. If that known ID names another issuer, it returns no owner. validateFirstTakeSubjects independently refuses a different issuing buyer before resolving any owner. Its native paid screenplay/director/cast check now applies unconditionally whenever the known production ID exists. Changing both issuer and screenplay ID to genuine seller values cannot bypass that branch. Live subject production derives the same context for a non-own concept regardless of the claimed issuer. Default historical callers without context retain their original behavior.

**Native first-take interval.** Each derived history entry now carries earliest/latest bounds from its independently validated greenlight, terminal receipt and native current clock. These are intervals, not an invented exact filming date:

- Greenlight input week G is skipped (`operations.ts:1658–1661`). A native production starts at remaining 8. Its first take is the 5→4 edge (`operations.ts:1680–1689`); the settle set permits at most one progress edge per input (`operations.ts:1802–1807`). The four earliest eligible inputs are G+1 through G+4. tick appends the take at the produced week (`tick.ts:1215–1219`, `promises.ts:155–160`). Therefore earliest = G+(8−4)+1 = G+5.
- At current/cancellation boundary B with remaining r≤4, at least 4−r advances happened after the take produced remaining 4. Therefore latest = B−(4−r). A cancellation with remaining 4 may follow a take in the same produced week: equality is allowed. A current/cancelled production still above 4 has no lawful first take yet, represented by no valid upper bound.
- A release decision names input week R (`markCarriedScriptProduced` receives tick's currentTick). From remaining 4, three later advances must reach 1 before the release input's 1→0 edge (`operations.ts:1750–1783`). Therefore latest = R−3. The released FilmResult likewise uses that input week as releaseTick (`tick.ts:670–672`).

Capacity, setup and unscheduled-take holds delay progress; none make an edge happen earlier. The inequalities allow all such pauses. They do not reconstruct a lost exact shooting date or require a fixed total production duration. The history's original greenlight is the source of the lower bound; the terminal receipt or actual current native production supplies the upper bound. No source/creator record or original close-time production is rewritten.

Exact new refusal strings remain `validateSaveV40: firstTakeSubjects facts[i] does not name its native issuing buyer` and `validateSaveV40: firstTakeSubjects facts[i] is outside its native production first-take interval`. The existing paid-project/crew refusal remains unchanged. All inputs are only read; no receipt or caller object is changed.
