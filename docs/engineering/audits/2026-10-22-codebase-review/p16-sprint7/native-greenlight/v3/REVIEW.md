# V3 focused first-take authority review

Patch hash `0c05d33b698811c9a24c2c77e4c8cac9dc0fca4768c8d024e6dd0d9d82c5e0fb` and all four postimage hashes verified. Static review only, against installed v2; no runtime or repository changes.

1. **HIGH — A known native production can fall through to the wrong issuer.** In firstTakeSubjects.ts, both takeSubjectOwner's native branch and validateFirstTakeSubjects' new crew/project check are conditional on `native.studioId === take.studioId`. If a retained native take is changed to the absorbed source studio, the resolver falls through to that rival business instead of refusing. Changing its fact.scriptProjectId to the genuine original source project then satisfies the rival concept/project checks; the new native crew/provenance check is skipped. The generic first-take validator checks only that the studio is entered, not that it issued this production. This is a source-inferred hostile route, not a reproduced full-save exploit. **Fix:** when productionScriptHistory contains the production ID, require its exact issuing buyer before any fallback, and enforce the native paid project/crew join unconditionally for that known ID. Preserve default behavior when no current-era authority is supplied. Add wrong-issuer plus original-source-project control with caller purity.

2. **MEDIUM — Native take timing is not bounded by its paid production history.** The new branch binds production/project/concept/crew but never joins take.week to the greenlight or cancellation/release interval. promises.ts only checks the general campaign recording interval; promise-specific windows do not establish production existence at that week. A take dated before its greenlight (but inside the campaign interval), or after an actual cancellation, is therefore not refused by this authority. **Fix:** expose/use the already-proved greenlight and terminal receipt weeks for this exact production, enforcing the native earliest-first-take rule and terminal bound without inventing an exact shooting date for paused work. Use the existing first-take clock law and preserve same-week action semantics. Add bounded wrong-week controls.

The proposed productionScriptHistory is otherwise an appropriate durable join for cancelled/re-greenlit productions: it retains the original production ID, buyer and project identity without moving source concepts or copying source scripts into the own root. Native crew checks bind all cast slots and director to the paid snapshot. The live producer derives context only when a player take lacks an own concept; frozen readers receive no new context unless explicitly supplied through current save descent. The current project link suffices for creating a fresh take, while the history map supports validating an older cancelled take after that link clears.

Resolve the two concrete authority gaps before treating the v3 correction as qualified. Types and genuine first-take/release continuation remain unrun, and prior lifecycle timings remain over budget. No broader v2 review was repeated.
