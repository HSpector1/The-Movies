# Source preparation lessons

These controls have not been executed. They test the original public sink and the same pure diagnostic factory and arm helper used by the fullbody source. They do not qualify a game, identify the failed natural row, or repair any historical STOP.

An integration claim needs the actual integration code. A test-side imitation of the catch/finally path would miss changes in the fullbody arm. The shared helper makes exact original Error identity, later unrelated errors, and cleanup precedence directly testable without importing the game.

Capture the original fatal row Error before emission and reset. A swallowed refusal can be followed by another body error; end and reset can fail as well. Both cleanup calls still run, while the original row Error remains fatal. Without that sticky row Error, the existing nested cleanup precedence remains unchanged.

The original witness uses JSON row plus newline accounting. Array serialization adds different framing and must not reject an otherwise legitimate prior-row stream at its exact 2MiB boundary. Count and total refusals also have different original messages and must not become row-byte diagnostics.

Diagnostic reconstruction can cause the resource problem it is trying to describe. Safe preflight must precede additional failed-row serialization, reject accessors and stateful serializers without invoking them again, and refuse unknown context extras rather than emit payloads or invent bytes for a modified row. Unavailable scalar metadata preserves the same original Error.

Expected RED means a specific authenticated refusal or error identity. Fixture setup, imports, unexpected schemas, and arbitrary exceptions are failures of the controls. A malformed synthetic provider fixture was corrected during source preparation and was never executed or counted as a RED result.
