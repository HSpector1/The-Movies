## Decision to review

The exported direct admission seam should default to the **live** finance law: `admitRivalPlans(state, era: 'recovery' | 'pre-recovery' = 'recovery')`. Its actual current callers in `tests/p13b-s8-finance.test.ts` (three calls) and `tests/p13b-s8-capacity.test.ts` (four calls) construct states with `p13aGeneratedStudio()` and retain no argument. They must use `moveRivalMoney(..., 'live')`, whose complete roster includes `termination` and `facilityDemolitionRefund`; the current r2 historical default makes those funded tests throw before admitting a Laboratory. The live weekly `admitRivalPlansInWeek` remains unchanged, still using its own B gate and live roster.

The genuine V27 callers must state their provenance explicitly: change only the two calls in `tests/p13b-s8-save-v27.test.ts` and the one call in `tests/save-masked-downgrade-own-era.test.ts` to `admitRivalPlans(..., 'pre-recovery')`. These inputs are already proven historical by the immutable V26 fixture and real V26→V27 lift, or by `validateSaveV26` followed by `convertV26ToV27`; the test does not infer era from a missing field. That branch skips the B cutting dereference and passes `research-v27` to `moveRivalMoney`, preserving the V27 roster and genuine Laboratory admission. The exact source change relative to EBG r2 is one default token at `src/core/rivalResearch.ts:202`; all other 187 production files and all nine existing E0G kit files retain r2 bytes. No C emitter, refund, facility disposal, `costCutting` validator, G writer guard, or saved-history law changes.

The accepted B-only design r3 says “retain E0G's explicit V27 finance seam and default historical behavior.” Thus changing the exported default to live is a **material design amendment**, even though it repairs the newly found current callers. Independent design review and parent adoption are required before building an EBG r3 candidate. If the reviewer rejects changing that default, the alternative is to keep r2's historical default and give the seven current test calls explicit `'recovery'`; that has a larger caller edit surface and leaves direct no-argument live callers unsafe, so it does not satisfy the requested live no-argument behavior. Do not choose it silently.
