Decision: **REFINE_STATIC_UNRUN**. This addendum supersedes the r3 `ACCEPT_SOURCE_ONLY_UNRUN` receipt SHA-256 `32dc1e7ca07be2615950076fabcf72d55bb2ecf057b9cdf5d8fee370b9f7dd94` for launch purposes. It does not change that review's successful tiny ACL/xattr, group-cleanup, and ordinary output tests. The frozen source was not edited; no real H/dependency tree, Vitest, heavy lane, or Git mutation was used.

Two protected-output blockers remain:

1. **Held-FD moved-parent write.** `recorder.py:460–463` rechecks `receiptDir`, then calls `safe_output.write_once`. `safe_output.py:63–73` writes relative to the held FD with no kernel write denial on protected roots. If the parent is renamed under a protected root after the recheck, `RESULT.json` is created there; the post-write recheck notices only after the protected tree was changed. The same pattern exists before `create_child` at `recorder.py:325–331`. `swapped_parent_red.py` did exactly this with disposable directories: a receipt appeared under a synthetic protected root after its parent was moved. This is a real write-boundary defect, not merely a missing STOP classification. A path recheck alone cannot remove the check/write race.
2. **Immutable receipt parents omitted from output protections.** `recorder.py:314–317` protects source, dependencies, H, production, evidence and listed guard roots. It omits the bound `probeReceipt` and `stage40Receipt` parent directories, and does not require `receiptDir` and output parent to be disjoint from those accepted immutable receipt parents or each other. The RED passed a scratch immutable-receipt parent as the candidate output parent with a source-only protected list and `safe_output.validate_parent` accepted `RESULT.json` there. A filled binding could therefore mutate an accepted receipt directory without any rename race. `require_binding` hashes those receipt files but does not constrain parent placement.

The RED's scratch temporary directories were removed by their owner. Cleanup and receipt work in `finally` at lines 426–466 have no outer whole-process timer.
