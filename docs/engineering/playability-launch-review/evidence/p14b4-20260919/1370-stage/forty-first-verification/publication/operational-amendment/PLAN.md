# Stage41 publisher scratch-parent concurrency amendment — DESIGN ONLY, UNRUN

Decision requested: independently review a **narrow operational threat model** for the single Stage41 evidence publication. This document authorizes no Git write, GitHub push, H/dependency activity, or heavy lane. Stage40 remains published at `eb58bc0042ebf0c02a16d0bdaa1f5734e1f5f9eb`; Stage41's 75-row map and independent source-map receipt retain their exact pins. Historical r1/r2 publisher REFINE receipts remain failures.

## Proposed scope

During the one recorded Stage41 publisher invocation, exclude a **concurrent external same-user process that renames either unique one-shot staging or output parent into a protected tree** while the publisher has an open file/directory descriptor there. This is a session coordination assumption, not a security guarantee against a malicious same-user actor. The publisher and its Git descendants themselves remain inside the inline macOS sandbox. The run must have one production writer, sole heavy-lane ownership, no overlapping agent/cleanup/backup job authorized to manipulate these scratch parents, unique newly created parents, and a preflight process/path audit showing no existing user process owns or references them. The exact parent paths and identities are pinned in a separately reviewed filled binding. If another actor appears, parent identity changes, a rename/watch event appears, or the agent cannot establish that coordination, STOP and do not push.

The motivation is concrete. R1's independent after-recheck RED delivered 28 bytes into a moved protected output directory through an already-open writable FD. R2's independent after-open/before-write RED reproduced the same class. R3's scratch comparison shows atomic no-replace `linkat` of fully closed staged files denies an output parent moved immediately before installation, with zero protected output bytes. It also shows a **residual staging-file RED**: if an external actor moves the writable staging parent after a staged file opens but before its write, the already-open FD can deliver staged bytes under protected. No pathname recheck, macOS sandbox path rule, or lane lock alone can rule out an uncooperative same-user renamer. This amendment explicitly excludes that actor for this controlled run; it does not claim r3 defeats the strong adversarial model.

## Boundaries retained

- Bootstrap still pins the actual live Git common parent, worktree, protected H, evidence checkout if present, source map, receipt/source directories, policy bytes, executables and exact Stage40 parent. The full publisher and descendants run under default-deny kernel write policy. Only the exact unique scratch staging/output parents and `/dev/null` are writable; no live Git object/ref/index writes. Git uses a scratch bare repo with read-only alternates and `GIT_OPTIONAL_LOCKS=0` for live read-only probes.
- Hold nofollow parent FDs; verify exact device/inode/mode ancestry and empty leaves before arming, after each phase, and after exit. Watch staging/output parents for rename/delete events as a STOP signal; watcher absence is not proof of no adversary. Buffer raw child output under caps, stage complete files, close them, then atomic no-replace install to output. Any denied link/write, moved parent, altered source/ref/receipt, ambiguous watcher, child failure, timeout, disk/AC failure, or uncertain group cleanup is STOP with evidence retained. No retry into an unsandboxed path.
- Use a single recorded heavy lane for publication with independent source and filled-exact reviews, additive private-index commit, compare-and-swap staging ref, nonforce remote push, and exact local/remote tree/delta proof. Push success is `REMOTE_BYTES_PENDING`; a later fresh independent HTTPS audit must verify all Stage41 source and publication-control bytes. No H type, C0 attribution, 1363, P16, game, or native acceptance follows.

## Admission judgment

The agent must document why the excluded actor is absent **at this particular invocation**: identify the single writer, owned process group/lane, unique parent path creation time and owner, any cooperating jobs or watchers, and lack of authorized concurrent rename/cleanup. This can establish coordinated-process behavior, not exclusion of every process with the same UID. Independent review should either accept this narrower risk explicitly, or reject it and require a genuinely non-renamable staging parent (for example, an independently provisioned parent owned by another principal) before any launch. If accepted, pin this design and its independent review in the exact Stage41 binding and result. Do not silently promote a source-only or synthetic receipt into run authority.
