## Materialization and write boundary

Run only after Stage40's remote **file bytes** are independently proven and new CURRENT production/evidence refs are filled and reviewed. Historical H source commit `8708d6a98e6eb4ad53e3a54e431c4b40b974f79d`, bridge tree `a697b042eccb85adacd40ef1303869be6d26239a`, four accepted overlays, original full-readback result, and r13 STOP remain separate pinned source roles. A new experiment is disposable and has its own root inode/timestamps; never reset or edit the protected H mirror.

Use a unique, one-shot scratch parent with two separately materialized trees: `control/` and `instrumented/`. Each has the H 1,402 regular files, exact contents/modes/OIDs and bridge overlays; compare regular-file paths, content and modes to the historical full-readback manifest and to the other, recording file count, 99,516,095 logical bytes, file digest, directory modes, owner, ACL/flags, and root entry roster. Normalize the deliberately relocated `node_modules` link target/length and new inode/timestamps in comparisons; any other deviation stops. Preserve the H root mode/owner/ACL/flags where possible; if they cannot be reproduced, stop before execution. Set the source trees' one `node_modules` link to their **own isolated dependency view** under that same scratch parent. Record the deliberate symlink-target difference from H, and inspect every dependency symlink: the observed 24 are expected to remain internal relative links; any absolute or escaping link is a stop. No hardlinks to the live repo or protected H mirror. Each isolated dependency view must be read back against a separately frozen path/content/mode/link manifest of the installed 12,484-entry, 348,223,802-logical-byte dependency tree (historical metadata digest `a06e929a60a5ede6ce0d72467d4d587e50d1c4fa3788bee3d07f1ea3388cd21d`); normalize copied inodes/timestamps/ownership only where explicitly reviewed, and include link targets, modes, flags, ACLs, and resolved realpaths. Do not use a read-only clone for the *first* control because that could force Vite's EACCES fallback; reproduce writable permission behavior first.

The child process and all descendants must run under one independently reviewed, **actual bound** macOS `sandbox-exec` profile. Freeze its full text and SHA and an absolute one-shot `sandbox-exec -f <profile> <resolved child executable> <argv>` template before either arm; control/instrumented bindings may change only the reviewed source/output paths and preloader injection. Deny `file-write*` under canonical live production, protected H mirror, evidence checkout, **all other accepted scratch receipts**, and one harmless dedicated `denied-canary/` under this experiment. After freezing the *same actual profile bytes and argv prefix* used for both arms, run a separately reviewed synthetic probe under that profile before **each** arm: a descendant process attempts a new file in `denied-canary/` and must get a denial with the file absent, then writes a new file to that arm's allowed one-shot probe output and must succeed; parent and descendant report effective profile SHA/argv prefix/identity, then the parent verifies inode/path/result. Require at least 4.0 GiB free before materialization and at least 3.0 GiB at every child preflight/postflight; if inadequate, wait for an authorized cleanup or reduce the experiment via separately reviewed design. ## Control then instrumented route

Use the same reviewed command in each copy, with only the necessary absolute scratch output and cwd substitutions: `vitest list tests/diagnostic.test.ts --project core --json <absolute one-shot collection.json> --no-cache`. Resolve Vitest from that copy's isolated dependencies. No root/UI tsc rerun is needed for attribution. Give each process its own recorded heavy lane invocation; never overlap lanes. Each has <=90-second child, <=120-second recorder, bounded stdout/stderr (8 MiB each), bounded watcher/event logs (4 MiB each), child process-group kill/reap, source/source-tree and dependency pre/post, AC, disk, exact refs, lock/survivor checks, and an independently reviewed exact launch. The lane wrapper's zero exit does not imply child success. Preserve all raw results, lane `.meta`, recorder, collection, event logs, hashes and cleanup proof. Settle briefly after child exit to collect delayed events and confirm no descendants remain.

Run a **control with no `NODE_OPTIONS` preloader** first. A watcher on the disposable root must be ready and attest its inode, watch start time, event-log cap, and no dropped/error state before the child. Sample root `lstat` tuple, roster and full source/dependency digests before and after. `fs.watch` on macOS may coalesce or omit filenames; it is a hint, not proof of no operation. Require the same diagnostic test to appear in the collection JSON and a root mtime/ctime transition with unchanged final roster/file digest for a comparable control. If control has no drift, collection differs, sandbox denies an operation, watcher fails, or source/dep guards fail, classify `NO_COMPARABLE_CONTROL_STOP`; do not run the instrumented arm under this design.

For the instrumented arm, inject only the independently SHA-reviewed scratch Node `--require` preloader via `NODE_OPTIONS`, without changing the command, dependency bytes, source files, sandbox, or permission modes. Preloader logging must use captured original APIs to write **outside** the source/dependency trees, with an append-only bounded log, no recursive instrumentation, and a hard truncation/refusal marker. Wrap the actual Vite paths (`fs/promises.mkdir`, `writeFile`, callback `fs.unlink`) and also relevant sync/callback/promise create/open/rename/unlink/rmdir/rm/write APIs, `FileHandle` writes and `createWriteStream`. **Also wrap root and direct-child metadata setters**: `utimes`/`lutimes`/`futimes` and their sync, callback, promise and FileHandle forms; `chmod`/`lchmod`/`fchmod`, `chown`/`lchown`/`fchown`, their available variants, plus any Node-visible xattr/flags APIs in the installed runtime or loaded native modules. Log attempted and successful metadata changes even when final mode/times match baseline. If a setter cannot be instrumented or a native/child actor may bypass the hooks, record that explicit coverage gap and prohibit an exclusive causal claim. Preserve original signatures, return values, callback/error behavior, and ordering as far as possible. Log start/end monotonic and wall time, PID, PPID, worker thread ID, op, original and resolved absolute path(s), result/error, and root tuple before/after direct-child mutations. Include both source and destination for rename. Avoid ambiguous asynchronous `lstat` ordering by recording a monotonic sequence and a synchronous root tuple at hook entry/completion where practical; overlapping operations require separate causation review.

Every Node process/worker thread that might load Vite must emit a startup attestation with PID/PPID/thread ID, preloader file SHA, effective `NODE_OPTIONS` and `execArgv`, before collection. The recorder captures a process/worker lineage and correlates the attestation to the PID/thread that logs Vite operations. `syncBuiltinESMExports()` can refresh builtin ESM bindings but is not complete coverage. Before either heavy lane, independently static-review the preloader and run bounded synthetic tests in scratch for sync/callback/promise/FileHandle/stream calls, all listed metadata setters (including root `utimes` with unchanged roster), callback errors, worker-thread and child-process propagation, no recursion, caps, and attestation. If an uninstrumented process/native path may have handled the root operation, if attestation is missing, if logging alters collection or root behavior, or if any log is truncated/dropped, classify `UNATTRIBUTED_STOP`.

## Causal decision and next route

Report `DISPOSABLE_DIAGNOSTIC_OPERATION_OBSERVED` only if: (1) the uninstrumented control reproduced a root timestamp transition and the same collected test; (2) the instrumented arm also reproduced both; (3) the event log shows a successful direct-child create/rename/unlink/mkdir/rmdir/rm at an exact absolute path, with attested PID/thread and lineage; (4) that operation's bracketed root tuple and time intersect the observed root transition, and a watcher event independently supports the same basename/interval; (5) the direct-child item is absent afterward, the final roster/digest/dependency proof matches, and no competing logged metadata setter or other logged operation overlaps the transition. This status identifies a matching operation in the disposable instrumented run, **not an exclusive historical actor**. Report the exact Vite path and EACCES/fallback branch only if its logged operations and installed source jointly establish it in that disposable run. A missing filename/event, multiple plausible logged actors, root metadata mutation, uninstrumented/native/child coverage gap, different control behavior, sandbox denial, altered source/dependency or preloader side effect leaves `UNATTRIBUTED_STOP` for causal attribution; preserve raw observations separately.

This experiment is limited by dependency target relocation and sandbox behavior. It cannot retroactively pass r13, establish that the historical live mirror took the same branch, waive the H root guard, or satisfy the full H type gate. Any remedy (for example redirecting Vite config temp to scratch) needs its own source/recorder/exact review and a fresh full H run from accepted baseline. Retain disposable trees and logs until separately reviewed evidence backup and cleanup; cleanup is not part of this design.
