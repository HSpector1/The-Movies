# H diagnostic root drift attribution r5 — disk/materialization amendment, unrun

## Authority and unchanged route

This is a proposed, versioned amendment to the accepted **design only** r4 plan (`b1f42ea4c301e04903e8bf2b4b7c8560724ab1c9407300481dda4d4730bc506a`) and its independent review (`f7ccb46627aad487f56a6f413e7f2d862d382c8412aeed7e9cc4944e2327ca6f`). It changes only r4's 4.0 GiB *initial* free-space admission and the method for materializing the two isolated scratch source/dependency views. All r4 source roles, Stage40 remote-byte gate, sandbox boundary, per-arm canary and descendant probe, watcher/preloader coverage, exact launch reviews, control comparability rule, 90/120-second limits, source/dep guards, >=3.0 GiB *throughout* floor, STOP classes, and narrow causal claim remain in force. R13 remains `STOP_POSTFLIGHT_DRIFT`; no H acceptance or historical attribution follows from this design.

No H tree or dependency view was materialized for this amendment. The r5 probe was a synthetic 2 MiB file and relative symlink in a fresh scratch directory. On this host, `man cp` says `-c` copies files with `clonefile(2)`, `-R -P` does not follow tree symlinks, and `-p` preserves modes, owner where allowed, flags, times, ACLs and extended attributes. The tested `/bin/cp -cRp` copied that synthetic tree twice on the same volume; a separate `/bin/cp -cRpP` synthetic copy also returned zero with a distinct destination inode, identical hash and retained relative link (exact-flags result SHA-256: `db6776d916e928a2e88bf7ee8a742b817fb7e47c7132a27fe2b6931acba3b635`); each destination had distinct content identity, retained the 0640 mode and relative link, and writing one clone changed only its hash. The observed extra allocation for that one 4 KiB write was 4 KiB. `du -sk` counted 6 MiB for source plus both clones although `statvfs` free bytes fell by about 2 MiB; therefore `du` is only a logical/accounting cross-check, not proof of unique physical allocation. Probe result SHA-256: `9dd803306d7afc6e4e2027616821705ecfa89a3aff7cb01927f4c747c50c0a03`. This probe proves the command works for a small same-volume case only, not that every real H file or extended attribute is cloneable or that clone savings have a guaranteed size.

At design time exact `statvfs` availability was 3,779,432,448 bytes (about 3.52 GiB), giving 558,206,976 bytes above the 3 GiB floor. Ordinary full copies of both source trees and dependency views could exceed that headroom; r4's 4 GiB admission is not met. The r5 route is *conditionally feasible* only if the reviewed real materializer confirms same-volume clone support, records actual allocated-byte deltas, and maintains the floor with a safety margin. If any precondition or margin fails, stop and request more free space; never silently fall back to ordinary byte copies, hardlinks, production-target symlinks, a shared writable dependency view, or lower disk thresholds.

## Clone-backed two-view materialization

Freeze and independently review the materializer source, argv, resolved source/destination paths and one-shot scratch parent before execution. The protected H mirror and installed dependency tree are read-only inputs. The destination parent and both `control/` and `instrumented/` trees must be on the *same APFS volume* as those inputs (`st_dev` and an actual small synthetic clone test for each source volume); no target may preexist. Resolve every input and output without symlink ambiguity before opening it. Acquire no write descriptor on a protected input. Use `/bin/cp -cRpP` into new one-shot destinations, with `LC_ALL=C`, separately for each source tree and each dependency tree; materializer must fail closed if `cp` returns nonzero or a regular file is copied as a hardlink, or clone support is unavailable. The reviewed workflow must call `cp -c` explicitly and must not retry without `-c`. Because `cp -c` does not itself emit per-file syscall evidence, its documented clone semantics, zero exit, same-volume checks, and unique inodes support the clone-backed route but do not measure each file's shared extents. If independent review requires per-file proof, use a separately reviewed direct clonefile(2) materializer with explicit return codes; otherwise stop. No unreviewed byte-copy fallback is allowed. Preserve r4's readback of paths, 1,402 H regular-file contents/modes, 99,516,095 logical bytes, bridge overlays, directories/owner/ACL/flags, and the 12,484-entry dependency manifest. Record source and destination `st_dev`, inode, link count, mode, link target and content hash for every entry; cloned regular files must have different inodes from protected inputs and from the other arm. Any hardlink, escaping dependency symlink, metadata mismatch outside reviewed normalization, or changed input guard is STOP before collection.

The only deliberate link rewrite is each arm's top-level `node_modules` link to *its own* isolated scratch dependency view. Verify all 24 internal dependency links and all resolved realpaths again after rewrite. Both arms remain independently writable, including their own dependency view. The control must retain original writable permissions, run without `NODE_OPTIONS`, and reproduce the root timestamp transition and collection result before an instrumented run is allowed. Neither arm may write its source or dependency tree while the other runs; guards detect this. Keep both materialized trees and raw results for independent inspection under r4 retention rules.

The exact H source and dependency manifests, protected H mirror guard, installed Vite SHA/source lines, current production/evidence refs and Stage40 remote-byte receipt must be bound in a later reviewed exact launch. This amendment itself authorizes no materialization or heavy-lane run.

## Byte accounting and disk admission

Use `statvfs(f_bavail * f_frsize)` on the destination filesystem as the authoritative *available-byte* measurement, and capture filesystem device, timestamp and source/destination `du -sk` as auxiliary figures. Define FLOOR = 3 * 2^30 bytes; set a 256 MiB operating buffer above FLOOR and a 128 MiB stop buffer for interval monitoring. Before creating the one-shot parent require free >= FLOOR + 256 MiB; if the initial reading has fallen below that, stop. Before/after each source/dependency clone step, metadata/readback step, canary probe, control launch and instrumented launch, record free bytes. Require free >= FLOOR + 256 MiB before each new clone or child; if free after a step is below FLOOR + 256 MiB, stop before the next step. A monitor sampling at least once per second during each materialization and child should stop that step if available bytes reach FLOOR + 128 MiB; any observed free < FLOOR is an unconditional `STOP_DISK_FLOOR` and cannot be waived by a later recovery. Reserve and account for bounded logs/output from r4 and expected CoW writes to either isolated dependency view; any observed allocation materially above the independent estimate requires STOP and review before proceeding. Record `statvfs` deltas after each *separate* source and dependency clone; do not infer physical savings from `du`, logical file size, the tiny probe, or `cp` exit status.

The clone source plus destination file data may share APFS extents; the distinct destination metadata and later copy-on-write data still consume space. No estimate here is an assurance of a floor during arbitrary concurrent host writes. The independently reviewed recorder must enforce the disk monitor, output caps, child-group termination, and pre/post guards; if these cannot be implemented or verified, use the original 4 GiB admission or obtain additional free space. At the design-time reading the total headroom above FLOOR was about 532 MiB, leaving about 276 MiB beyond the 256 MiB admission buffer. The real-tree materializer must fit its metadata, copied non-cloneable content (if any; fallback is forbidden), output and CoW demand inside measured headroom. If it cannot, r5 cannot safely reach attribution without more disk.

## Review and decision

Require independent review of this r5 amendment, exact materializer and static/probe evidence before any real H copy. Then keep r4's sequence: exact Stage40 remote-byte proof; current-ref and source-role binding; sandbox profile and synthetic canary/descendant probes; preloader static and synthetic coverage; independently reviewed control exact lane and observed comparable drift; independently reviewed instrumented exact lane and narrow attribution review. The r4 no-comparable-control and unattributed stops remain mandatory. A successful clone-backed materialization only opens those later gates; it is not an H type pass.
