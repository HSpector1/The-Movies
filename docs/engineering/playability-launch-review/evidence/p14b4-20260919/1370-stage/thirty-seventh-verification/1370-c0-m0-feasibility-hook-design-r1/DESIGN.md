## Narrow contract

Introduce one scratch-only diagnostic module, for example `src/core/m0FeasibilityWitness.ts`, shared by the *isolated overlay copies* of `talentMarket.ts`, `promises.ts`, and modern `opportunityPromises.ts`. It owns a bounded append-only side channel outside `GameState`; it must not import or invoke any decision helper, mutate a game object, create a RNG stream, or write a save. Keep the production call graph's one existing `promiseFeasibility` invocation per visited candidate/freeze read. No hook is installed in the live repo.

Pass an **optional synchronous capture parameter** only down the actual call path, rather than using a process-global context or re-running `promiseFeasibility`. It is an inert `undefined` for every ordinary caller. At market's existing authoring call, bind context `{phase:'authorCandidate', era, week, caseId, subject, issuer, candidateOrdinal, proposalDigest}`; at the existing target freeze `attachedFeasibility` call, bind `{phase:'freezeProposal', ..., submittedOrdinal}`; at a later chooser re-read, bind `{phase:'chooserBand', ..., survivorOrdinal}`. Pass this exact context through `promiseFeasibility` to `receipt` and, in modern opportunity cases, to `opportunityAssessment`. The callback accepts copied data only, returns `void`, and must be rejected if it attempts nested capture/re-entry. A thrown bound or serialization failure stops the diagnostic route; it is never caught as a game refusal.

Emit these semantic events, each keyed by context plus source-order occurrence:

1. `inputTuple`: the **same canonical serialized bytes** that `receipt` hashes for `inputsDigest`, with tuple schema/era, byte count, actual digest, and exact serialized value if within the observer cap. H's `receipt` currently computes `fnv1a64(JSON.stringify(inputs))`; bind that serialization once and reuse it for digest **and** capture. M0's `receipt` currently computes `fnv1a64(serializeFeasibilityInputs(inputs))`; bind that one sorted-object-key serialization once and reuse it. Do not independently serialize with a different replacer or re-read `feasibilityInputs`. Preserve all existing digest bytes. If 16 KiB row or 2 MiB total cap is exceeded, fail closed before side-channel append; do not truncate, sample or substitute only a hash. A versioned larger/chunked bounded form needs separate review after measurement.
2. `assessment`: the classification, bottleneck, rulesVersion and week actually returned by `receipt`, paired with the same input event. For H, carry local `X/from/reserved/nMax/existingPath/lastEventWeek` only when those branches really computed them; mark nonreached fields `NOT_EVALUATED`. For M0, also carry actual `opportunityScope`/directing-scope flag, occupancy/reservation counts, retirement state, and branch-local values, never computed for logging alone. A receipt class difference with equal captured input tuple is a changed decision, not an inferred input change.
3. M0 opportunity-only `opportunityAssessment`: at its existing `paths(...)` result, capture bounded candidate path scalars (ID, production ID or null, takeWeek, freshWeek, physical, uncertainty) in source order; inside the existing loop, capture whether each candidate was skipped, its *already-computed* `reservationWitness` and `delayed` path result only when those branches run, and the returned classification/bottleneck. Mark post-early-return candidates `NOT_EVALUATED`. H emits one `NOT_PRESENT_IN_ERA` marker for this event family; it must not call an opportunity helper.

The callback must never receive `state`, mutable production/promises/operations objects, or a newly constructed copy of an input tuple obtained by helper calls. It may receive the already serialized immutable input string and selected local primitive values. Use the r4 step12 sink's 512-row/16 KiB-row/2 MiB-total checks, or a separately reviewed versioned cap if exact source data exceeds them. Connect events to market rows by context and occurrence, not by digest alone. All events remain diagnostic and outside save/RNG.

## Synthetic no-extra-call and refusal tests before any route

- **Serialization identity:** given small synthetic `inputs`, instrumented H and M0 `receipt` return byte-identical `inputsDigest`, class, bottleneck, version and week to uninstrumented functions. H's original `JSON.stringify` order and M0's sorted-object-key serialization are separate expected values. One serialization call per receipt in both arms; callback sees exactly the serialized bytes used for the digest.
- **Call counts:** AST plus spy tests assert one `promiseFeasibility` per visited market candidate; one `feasibilityInputs` per promise call; no second `opportunityFeasibilityInputs`, `opportunityAssessment`, `paths`, `reservationWitness`, `isProven`, `rivalProposalTrigger`, `submitProposal`, or RNG/stream call. Compare original versus instrumented calls for accepted, impossible, fragile and early-stop paths in both eras.
- **Context isolation:** ordinary callers with no optional parameter emit zero rows; target author/freeze/chooser contexts emit only their own rows; two same-week same-issuer candidates retain distinct ordinals; nested/re-entrant use refuses; a thrown observer cap error propagates out of diagnostic code and is not swallowed by the proposal refusal catch.
- **Bounds and purity:** synthetic 16 KiB-per-row, 2 MiB-total and 512-row limit REDs; exact-boundary passes; one-byte-over fails before append; cyclic/unserializable diagnostic detail fails closed. Freeze a before/after game-state preimage and RNG counter for the synthetic call; assert unchanged. H opportunity is `NOT_PRESENT_IN_ERA`, not evaluated. M0 opportunity path tests cover early success and all-fail paths with explicit `NOT_EVALUATED` suffix.
- **Static differential:** only optional observer argument plumbing and already-computed local capture may differ in the decision function bodies; compile with exact era source trees. Independently review full-file hunk hashes, the new module, fixture and test before types or any full 416-week route.

## Stop conditions

If the canonical input bytes cannot fit within the reviewed caps, the source-diagnostic callback changes a protected digest/RNG, a decision helper call count changes, a caught refusal absorbs an observer failure, or opportunity path values require an extra evaluation, stop and version a correction. Never use an `inputsDigest` alone as proof of exact input equality or an observer row as proof of causal game impact.
