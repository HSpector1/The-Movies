## Static candidates, ranked

1. **Vite config bundle temporary file fallback, conditional.** This is a concrete create/delete path under the mirror root *if* Vite cannot use `node_modules/.vite-temp`. Installed Vite 6 `node_modules/vite/dist/node/chunks/dep-Dm0c1Wj2.js:49569-49595` calls `findNearestNodeModules`, tries `mkdir(nodeModulesDir/.vite-temp)`, then writes `${fileName}.timestamp-*.mjs` beside the config file when no usable `nodeModulesDir` exists, and unlinks it after import. For root `vitest.config.ts` or `vitest.workspace.ts`, fallback makes a temporary mirror-root entry and yields exactly an unchanged final roster with changed root mtime/ctime. But `findNearestNodeModules` at lines 6381-6391 uses `stat` and should accept the mirror's `node_modules` symlink to the production directory. The observed unchanged production dependency content/metadata makes a normal `.vite-temp` write less likely as well. Thus fallback is a focused hypothesis, not proven; log the actual resolved temp path and fallback reason before ranking it causal.
2. **Another transient root write during Vitest startup, from a plugin or concurrent process.** The workspace config at `vitest.workspace.ts:14-38` defines core and UI projects; the root config at `vitest.config.ts:1-8` has no explicit cache or root-output path. `--no-cache` disables Vitest result cache, but the Vite config loader still runs. A process external to Vitest could also create/remove a root entry in this seven-second window. The snapshots cannot distinguish ownership. Trace by PID/path rather than attributing based on timing.
3. **Vitest typecheck temporary tsconfig, lower priority.** Installed Vitest `node_modules/vitest/dist/chunks/RandomSequencer.CMRlh2v4.js:560-584,818-841` writes `tsconfig.vitest-temp.json` beside the root tsconfig and later removes it. That would fit root timestamps, but the reviewed root/workspace configs do not enable Vitest typecheck, and this is a `list` invocation. Check whether that code path was entered before treating it as cause.

Two obvious outputs are outside the mirror root: the diagnostic test module creates `PREIMAGE_OUTPUT` at mirror `tests/diagnostic.test.ts:16-18`, but the binding points it into a scratch result path; Vitest JSON output is written to the absolute scratch `collection.json` via `node_modules/vitest/dist/chunks/cli-api.DqsSTaIi.js:11947-11955`.
