# Major lessons from the AQ diagnostic repair

1. **Independent test authors can overturn an accepted source review.** The first diagnostic repair still let unknown codec exceptions reach a spoofable error field or getter. The test author caught it before runtime. Preserve the initial source and review, explicitly withdraw the acceptance, fix the narrow defect, and obtain fresh independent review. Do not silently edit a review to erase the mistake.

2. **Assertions inside a callback that catches errors can give a false pass.** The diagnostic writer deliberately contains writer failures. A test assertion inside that callback could therefore disappear. Retain the observed data and a call marker, throw the intended writer error, then assert the observations outside the callback after verifying the original error identity. The corrected controls kept the same case roster.

3. **Check the paths and fields the program actually evaluates.** Replacing a full path string can miss a separately assembled basename. A schema name can be valid yet belong to the wrong producer. Verify evaluated path constants, every accessed key, non-map recipe fields and actual producer labels. Preserve historical tool observations according to the roles they really contain; do not invent missing compiler or helper fields.

4. **Keep authority references acyclic.** An unrun draft expected an adoption artifact to contain its own physical role. Its static audit caught the mistake. An adoption references already-existing reviewed predecessors; the later runtime grant references the completed adoption. Never invent a future hash or create a circular receipt dependency.

5. **A focused pass is a measured win with a defined scope.** Actual session 58815 passed all 86 diagnostic controls: 13 positive and 73 specific refusals, preserving the original 72 cases and adding 14. Recorder time was 3.432947114983108 seconds. Independent review 8df85592 and root adoption 385249 admit the exact result, module identities and cleanup. The inherited helper warning remains recorded. This does not prove the full scenario fits its limits or close the ledger, P16, P17 or P18.

6. **Measure protection cost and distinguish it from game proof.** The current AP full scan took 459.9390340069949 seconds, including 343.83853859000374 seconds in inventory. Independent review 53f7b6fa and root adoption 4bd6fe37 accepted its complete maps and nine roots. The separately reviewed short check reused that actual baseline under continuous protection and refreshed the original live checks. Neither result supplies missing game AFTER proofs; the complete postflight remains mandatory after the scenario attempt.

7. **A push, a tracking ref and a complete backup are separate checks.** AP was correctly advertised on GitHub, but plain fetch did not refresh this branch's tracking ref. An explicit source:destination refspec fixed it; no second push was needed. Verify advertised refs, local tracking, ancestry, source identity and cleanliness separately. Compare the whole expected archive set and every indexed byte, including ignored files. Preserve authenticated diff-context whitespace and old verification logs rather than normalizing evidence to pass a check.

8. **Sending a message does not restart a completed agent.** The final source package was ready, but its reviewer had completed the preliminary task. Queuing the final files alone left the agent idle. Root detected this through the agent list and explicitly resumed it with a follow-up task. Use a follow-up task to restart completed agents and verify their actual status before reporting a review as running. This was an orchestration delay, not a test or source failure.

9. Validate the generated program, not only its wrapper and inverse mappings. Actual AQ fullfunction 42397 stopped in generation because runtime/core.test.ts retained the old AO HEAD f2f97c62 while the correctly protected live AP HEAD was d20347b8. The review had authenticated route bindings but missed a literal inside generated test source. Preserve this real STOP; inspect every current-versus-historical assertion in the evaluated generated source and add a source check before another expensive attempt. This result says nothing new about observer fit: generation stopped before baseline, mutant, or diagnostic execution.

10. Preserve comparison evidence on failure, not only on success. Mandatory shared postflight54871 failed the original final immutable equality predicate after the full scan. The original scanner writes its maps only after that predicate, leaving no actual compared map to diagnose. Do not infer a changed file or rebaseline from the error alone. A separately reviewed wrapper can preserve exact original scanner identity and exception while retaining bounded in-memory comparison metadata; any later scan remains a separate observation and cannot retroactively pass this failure. Whole-source inverse equality proves a bounded edit, not that inherited assumptions remain correct.

11. Authenticate diagnostic attribution to the actual function code, not just a filename and line number. Independent review caught that synthetic code could imitate those coordinates. The corrected wrapper compiles the authenticated original source without executing it, matches its main code object and exact predicate frame, and always rethrows the original exception even when metadata encoding or writing fails. Actual pure32 (93221) passed9positive+23specific refusal cases in1.1601861900126096 recorder seconds, including impostor/duplicate frames, exact byte limits, integer/string key identity, and failure precedence. This is a measured diagnostic-mechanism win, not original-guard or gameplay acceptance.

12. Follow actual producer semantics when archiving evidence. Independent review found that the draft archive builder excluded three named fixture packets but omitted the actual fullfunction producer's fixtures.json packet. Fresh R2 refuses all four before reading, hashing, or parsing them. The source finding and fix were preserved before any archive execution; no payload disclosure occurred.

13. Environment sanitization can accidentally remove a safety setting. The inherited proof helper drops every GIT_ variable, including GIT_OPTIONAL_LOCKS=0, before invoking git status. The original full scanner's helper explicitly restores that setting. Review nested subprocess environments, not only the root launcher. Source finding89510545 proves this defect; the worktree index timestamp12:11:03 falls within the actual fullfunction12:10:59–12:11:44 recording. This is a concrete mutation mechanism and temporal lead, not proof that the index alone caused the original aggregate digest change. Historical source and failed attempts must remain unchanged.
