# Independent r3 launch-command design review

Decision: **ACCEPT_DESIGN_ONLY**, scoped to the exact proposal LAUNCH-SPEC SHA-256 `85b13895ab8ae42517fb1a3e489bc7953035272b3b0c17de31c773236ed65ecc` and PLAN SHA-256 `f1e608c0c6c317d0f8941fd5133ec4c831cf7dee928c10cd0eb01353b24f10e6`. No launch, binding adoption, or Git change occurred.

The structured argv has seven exact elements: pinned regular `/bin/bash`, accepted mode-0644 r8 helper, `0` wait-PID sentinel, unique absolute lane log, resolved regular Python 3.14.4 executable, accepted r4 supervisor, and original r3 binding path. It matches `lane-run-r8.sh`'s `<wait-pid> <log> <command...>` interface. All declared role hashes, regular-file types and modes matched in read-only checks. The lane parent is mode 0700; log, meta and global lock were absent at review. Local HEAD remained 5020e56e018c3acdeff6c93980ce05d31ac78847.

The helper can wait up to two hours for the global lock and up to 60 minutes for heavy Vitest/tsc, before it starts the r4 supervisor. Its `waiting for pid 0`, `start`, and final `end, exit N` metadata must be interpreted separately. The supervisor's 930-second OS alarm begins at its own entry, not at helper invocation. This design accepts that boundary only with fresh idle/lock preflight, a parent that treats any unexpected pre-child wait or interruption as STOP, and exact observation of one final meta exit matching the actual helper return and independently observed child exit. An overall 930-second wrapper claim is unsupported.

The spec pins the **draft** binding bytes `81204ed08795e3541633109db8a1009b362aaaaaf5efb43da1585b41b3f2abc0`. Adoption must change exactly the validator-excluded five fields, so this draft hash must never be used as the adopted launch checksum. Before any launch, archive and verify the original draft, inspect the five-field diff and adopted canonical semantic hash `f044d047fa62866ac7b8d8b0b6029b5653a4ebf08adbb9ad341a4eca08123fa4`, compute and independently review the *new adopted binding byte SHA-256*, and have a launch record that explicitly binds that checksum to this argv. The supervisor itself rereads the same binding bytes after the worker; that check does not replace prelaunch adoption review.

At launch, recheck exact physical roles, local/remote HEAD, clean source, source/tool hashes, dependency and protected roots, old PID/FD facts, free floor, no external same-UID renamer, exclusive global lock and idle heavy processes. Afterward, inspect the actual helper return, exactly one final meta exit, worker/supervisor results, any authoritative `SUPERVISOR-OVERRIDE-STOP.json`, owned group clearance, lock cleanup, physical bytes/allocation and protected-root/FD state. An override STOP or any mismatch is STOP. This design receipt grants no execution authority.
