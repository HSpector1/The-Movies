## 3. Blocking items

**1. Rule 4's prose names the wrong receipt week.** `1332-A` line 95: *"otherwise the subject keeps its week-207 receipt unchanged."* This contradicts the plan's own Attribution §3 (line 51: *"Both keep `contractId` null and their week-196 receipts"*) and every digest-facts log, which show `promise-3`/`promise-26` at `receipt.week: 196`, not 207. (207 is the *starting tick* of the fixture, per line 42 — a different number entirely.) Fix: change line 95 to "week-196 receipt," or better, drop the specific number and say "its existing receipt, unchanged" since rule 4 already requires deriving dynamically rather than hardcoding. Low effort, but load-bearing: this is the exact sentence the test-author will follow when writing the derivation, and if taken literally it names the wrong value.

**2. Rule 3's `firstTakeSubjects` guard doesn't check the content it's about to discard.** The proposed guard — *"throw unless every stripped `firstTakeSubjects` fact names a take present in `state.firstTakes`"* — only checks `fact.eventId` against `state.firstTakes`. It says nothing about `conceptId`, `genre`, or `scriptProjectId`, which are the actual "opportunity terms" payload (per `save.ts:10483`'s own comment) and are the fields the counterfactual probe shows are non-trivial: `{"eventId":"first-take-event-24","conceptId":"c-00","genre":"comedy","scriptProjectId":null}`. I grepped `tests/p14b5-relationships.test.ts` for `conceptId`, `scriptProjectId`, and `firstTakeSubjects`: zero matches outside the strip site itself. Nothing else in the file checks these three fields. Before this repair, they were covered (any drift moved the whole-state digest and failed the CANNOT-MOVE pin); after a bare existence-check strip, drift in any of the three would be silently invisible. This is a real weakening under 1327-A rule 3 / R3 rule 5's own "no assertion weakened" standard, not a hypothetical one — and it's cheap to close, since the exact expected value is already measured and matches the file's existing `FROZEN.takeEventId` constant (`tests/p14b5-relationships.test.ts:127`). Fix: tighten the guard to assert the fact's full expected shape (length 1, `eventId === FROZEN.takeEventId`, `conceptId`/`genre`/`scriptProjectId` matching the take's real values) rather than a bare existence check.
