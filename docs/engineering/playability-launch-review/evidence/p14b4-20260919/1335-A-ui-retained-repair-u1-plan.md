changed since 1322 ([1331-I](1331-I-broad-ui-attribution.md)). Ten of them are C3/C4, the missing `PIL` Python module:

## Rules

1. UI test files only: the five named `ui/src/lot/*.test.tsx` files and the one contract test. No production code,
   fixture payload, `vitest.workspace.ts`, `vitest.config.ts` or `ui/src/test/setup.ts` change. No project-wide
   budget.
2. C5: both leaves read the fixture through the app's own load path, `migrateToLive(loadSave(raw)).state`, with a
   comment citing `ui/src/engine/adapter.ts:3796`. No assertion changes.
3. M2: each named leaf gets an explicit per-leaf budget, the file's own form `}, 30_000)` (the precedent is
   `livingTurn.scheduler.test.tsx:373`, `}, 15_000)`). 30 000 ms is about 3× the slowest leaf measured alone
   (10 317 ms). The budget is the only change to the leaf.
4. M1: the first Lot mount in each named file must not race `findBy`'s 1000 ms default on a cold chunk. The author
   chooses one mechanism and applies it the same way in every named file: an explicit `findBy` timeout on the mount
   helper's first `studio-lot-screen` wait, or a `beforeAll` that awaits the lazy module. The author reports which one
   and why. Later assertions keep their defaults.
5. No assertion is weakened, removed or skipped. A budget measures time; it asserts nothing about the Lot's behaviour.
   None of these leaves is a performance test. The author states for each leaf what it asserts, and that the budget
   leaves it unchanged.
6. The author runs each touched file whole in the scratch tree, twice, and reports every leaf's duration. A leaf that
   still fails is reported with its measured facts, never forced.
7. C3/C4 (`PIL`), C6 (observed only) and `StudioLotScreen:930` stay untouched.
