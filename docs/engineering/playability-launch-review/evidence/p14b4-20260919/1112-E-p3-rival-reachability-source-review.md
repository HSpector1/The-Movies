For a current primary Actor in an ordinary case, the requested Actor and current-primary retirement records are the same fact.

Missing acting skills cannot create a genuine exception. Full Save admission requires exact complete discipline keys and profiles (`src/core/save.ts:1761–1799`), and Full Custom creation builds all disciplines (`src/core/actions.ts:875–899`). The missing-profile negative is useful for refusal testing, but cannot establish the public-created positive route.

Consider the first prospective explicit P3 for a primary Actor who has no pre-existing Director seat belonging to that rival. Under 1112-A's shared fresh clock, buffer, slack and scripts rules, P3's existing paths are the rival's unproduced scripts. P1 has those same paths plus any qualifying cast seat. Both candidates use count one and the same proposed term. P3's revision-6 reservation union is at least the old beneficiary-only reservation set; if an existing P3 activates revision 6 for P1, both use the same selected union. Thus that change does not create a smaller reservation cost for P3 (`src/core/promises.ts:250–280`, `:304–319`, `:491–529`; 1112-A:62–91).

The existing cast clock does not overturn that comparison in a genuine current trajectory. Rival productions start at eight remaining ticks (`src/core/hollywoodTick.ts:211`; `src/core/tuning.ts:59`) and then hold or count downward. At `from`, the actual cast-seat estimate is `from + max(1, remainingTicks - 4) + start-week adjustment`, at most the fresh five-week estimate. Later sequential event estimates use the same cycle (`src/core/promises.ts:374–394`; `src/core/operations.ts:1431`, `:1680–1684`, `:1751`). A fabricated oversized countdown would not be a public-route counterexample.

On those stated premises, an achievable P3 implies that the earlier P1 fallback is also achievable. The policy therefore selects a cast promise before it can create the first Actor P3. This is a bounded source induction for the proposed ordinary rival route, not a theorem about arbitrary imported records, every domain-specific future feasibility change, or all non-Director people.

## A favorable existing Director seat cannot be assumed

Current ordinary rival production chooses a primary Director (`src/core/hollywoodTick.ts:187`). Its package selector permutes the chosen cast and does not change that Director. The new promised-Director branch would require an already authored and bound P3. Using that branch to create the first favorable Actor Director-seat quote is circular.

Public player-directed work can establish directing skill/work history but belongs to the player's issuer; it does not create a rival-owned held path in `studioProductions`. C.3 changes Actor to Director or Writer and never Director back to Actor (`src/core/professionTransitions.ts:166–180`), so a former primary Director cannot supply the required current primary-Actor rival seat through that transition law.

A transitioned Writer with completed acting retirement is a materially different possible non-Director case: acting admission can be closed while directing remains lawful. It could disprove an overbroad claim about all non-Directors, but it does not exercise the primary-Actor fallback exclusion required by 1112-C. No natural Writer P3 route is claimed here.
