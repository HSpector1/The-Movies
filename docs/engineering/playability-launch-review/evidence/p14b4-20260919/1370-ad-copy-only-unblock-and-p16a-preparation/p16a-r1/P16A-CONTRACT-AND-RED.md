## Authority and scope

Owner mandates: P16 owns StoryProperty, rights, title and library truth; film/studio/concept creator identities remain permanent; property value is a read model and creates no cash; P16A precedes P16B/C. These come from P16 corrected register (`084713980ef8:docs/research/p16-independent-verification-01/P16-CORRECTED-DECISION-REGISTER.md` §§1–3), the authorized remainder plan §5, and `1367-O` branch-right ruling. `1362-O` §§5.1–5.9 governs later estate/transaction paths: existing grants and creator history survive sales, only unsold estate rights archive, and finance/people rules are qualified. The existing P16 integration contract §3 chooses the greenlight mint, four-right mapping, lazy predecessor derivation and live-grant constraints; its reviewer approved contract adoption, not runtime.

Implementation choices below are proposed under the parent charter's delegated rule-authoring authority, not verbatim Owner economics: exact ID spelling, array/event schemas, zero-copy legacy derivation, and the provisional valuation coefficients. No additional Owner choice is presently identified. If a future design would make an unpromoted branch independently saleable or give a title to a closed estate without a typed handoff, that would cross settled law and must be refused rather than inferred.

## P16A persisted law, proposed exact shape

Add one additive, versioned P16 root at the first free save era **when the actual predecessor is known**; do not reserve V46 from this old source. It stores `properties`, `filmTitles`, `titleEvents`, `licences`, and `recordedFromWeek` in canonical ID/order. One producer owns the arrays and their validation. `propertyId = 'story-property:' + founding conceptId` is an exact reversible ID only if the actual concept grammar admits it without collision; otherwise choose an injective encoding before RED. A `StoryProperty` stores immutable `propertyId`, `originConceptId`, `creatorStudioId`, `createdWeek`, `titleAtCreation`, `origin` and append-only distinct work links. A `FilmTitle` stores immutable `filmId`, `propertyId`, `creatorStudioId`, `releasedWeek`, original title, and one R2 holder derived from title events. A title event stores stable ID/ordinal/week, subject/right, prior/new holder, cause and authentic transaction or founding reference. The initial founding event has the creator as holder; no event can rewrite the creator or prior chain. Live current ownership is a fold over events, never a duplicate cached owner field. Later title-sale events belong to P16B; P16A writes only founding/legacy provenance.

Four rights have different subjects and transfer semantics:

| Right | Current authority | P16A assertion and P16B/P17/P18 boundary |
|---|---|---|
| R1 property | Exactly one current holder per StoryProperty | Original greenlight mints it atomically. Whole-title sale later; existing R3/R4 encumbrances survive. |
| R2 film/library | Exactly one current holder per released FilmId, independent of R1 | Release creates the R2 title with immutable creator. Whole-title sale later; no generic R2 licence. |
| R3 continuation | Default from current R1 holder, subject to a scoped exclusive term grant | Not independently sold title. P17 requests exact use and week; P16 resolves live authority. |
| R4 cross-media | Derived from relevant R1 property or R2 film title | Exclusive or nonexclusive scoped term grant only once a real P18 consumer exists. No territorial subdivision now. |

One future Licence record has stable ID; right R3/R4; exact property/film subject; enumerated use/scope; grantor and grantee; exclusivity; effective half-open `[startWeek,endWeek)`; consideration reference; expiry/reversion terms; and source transaction. P16A establishes type/validation and an empty legacy licence set; P16B owns executable grants and payment. Refuse unknown subject, overlapping exclusive use/interval, grant beyond grantor's right, expired use, and sublicensing without explicit authority. Resolve rights from current title plus valid grants at the requested week. A title transfer does not terminate a preexisting grant. No standalone branch/character right: until an explicit P16 promotion event creates a new property with parent provenance and preserved encumbrances, every branch use resolves against the parent R1/R3. P17 supplies branch payload and consumes lookup; it never writes title.

For an original player or rival greenlight, mint property and first R1 title event in the same accepted state transition as production. A failed/refused action leaves both absent and does not consume an ID. A later licensed continuation adds one work link to its existing property, not another unencumbered R1. At release, attach exactly one R2 FilmTitle and founding event to the actual FilmId, preserving the original producer/creator. Authored-start rival films and pre-P16 released player/rival films derive historical R1/R2 provenance from their genuine immutable `conceptId`, `filmId`, creator and date; migrate old saves with an empty P16 root and lazily materialize only on first lawful P16 use. The derivation is stable across save/reload and never invents a historical sale or awards rights to the current caller. If concept-to-property identity is ambiguous, or closure/estate status cannot be established, refuse the materialization pending an authoritative source; never guess that creator still owns saleable title.

## Valuation v1, provisional and cashless

`libraryValuationV1(state, holderId, asOfWeek)` is a pure integer-dollar read model. Each released film with valid R2 title held by that studio contributes `round(100000 * clamp(criticScore,0,100) / 100)`; authored rival films use their persisted criticScore, simulated player/rival films their persisted FilmResult criticScore. Each R1 property held by that studio contributes a distinct option premium `round(25000 * maxQuality / 100)`, where `maxQuality` is the highest persisted criticScore of released linked works, or zero when none. Count each FilmId once by R2 holder and each PropertyId once by R1 holder. R3/R4 term interests contribute zero title value in v1; their consideration belongs to P16B. Clamp only validated 0–100 scores, refuse malformed scores and dangling links rather than repair them. No in-flight/shelved work gets film catalogue value. Fixed integer coefficients are deliberately small provisional tuning, **not** accepted Owner prices or a sale/auction reserve; a later version changes the read-model version and preserves quoted snapshots. Value is never credited to cash, weekly revenue, Standing, Ranking, Legacy, or an instant reissue. Book net worth, enterprise value, offer price and clearing price remain separate later models; do not alias this library number to any of them. Verify current critic-score range before adopting these coefficients and field mapping.

## Independent RED design before production

Author tests against the then-accepted predecessor with real valid state builders, independently review the RED, run under the single recorded lane, then implement/review/measure. A missing root/compiler error is setup, not semantic RED. Targeted cases:

1. Original player and rival accepted greenlights each mint exactly one stable property/R1 event; an otherwise-valid refusal leaves campaign, cash, RNG, queued work and P16 root byte-identical. Save/reload/replay give the same IDs and event order.
2. Actual release adds exactly one R2 film title and work link; canceled in-flight work leaves its genuine R1 history but no invented R2 catalogue film; repeated tick/load cannot duplicate either. Existing `FilmIdentity.studioId`/FilmResult concepts and original credits stay unchanged.
3. Authored-start and pre-P16 player/rival works lazily derive matching creator/title identities from real records. Migration adds empty authority only; no global historical rewrite, speculative transaction, caller windfall or closed-estate free claim. Ambiguous/missing creator, duplicate IDs, mismatched release/film concept and dangling title event are rejected from otherwise-valid states.
4. Separate R1 and R2 holders yield separate option and film value; changing a property holder cannot move film creator or R2 value. A live R3/R4 encumbrance survives an R1/R2 sale in future P16B integration. Branch remains parent-bound until a lawful promotion; promotion preserves parent provenance and grants.
5. Exclusive grants reject same-use overlapping intervals, unknown subjects, unauthorized grantor/sublicence and expiry; non-overlap and legal nonexclusive R4 coexistence resolve deterministically. R4 execution remains closed until the P18 grant consumer is real.
6. Exact valuation arithmetic at score 0, midpoint and 100, multiple works, split holders, malformed score, title change and repeat read. No ledger, rival period, ranking/Standing or Legacy mutation; no added RNG draw; whole-game save/replay stable.
7. New-era validators and older-reader/downgrade refusals preserve existing byte input on rejection. Run generated DTO/schema consumers, focused core plus affected broad checks after actual implementation, not from this paper draft.
