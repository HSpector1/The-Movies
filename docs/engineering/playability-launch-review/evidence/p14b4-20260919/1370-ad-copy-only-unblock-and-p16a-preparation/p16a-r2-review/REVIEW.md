## Remaining material ambiguity: old finite critic scores

The draft states both that older frozen film readers may accept any finite critic score and that “P16 must validate `[0,100]` on every joined film,” with an A1 RED that makes an out-of-range finite score “refuse.” It does not say **which boundary refuses**. `src/core/save.ts:2015–2061` uses `v8Number` for `FilmResult.criticScore`, checking finiteness only. `validateSaveV45` calls its frozen predecessor chain, and a pre-2040 `campaignLegacy.official:null` returns before Legacy's score source validation; therefore a genuinely valid predecessor save can carry a finite score outside `[0,100]`. `campaignLegacy.ts`'s separate generated fact validator demands `[0,100]`, and the current reception producer clamps generated scores, but neither fact retroactively tightens the frozen save reader.

The next revision must explicitly distinguish save admission from a P16 valuation/transaction consumer. Preserve acceptance and lossless migration of every save valid under its genuine predecessor, including an out-of-range finite historical score; do not change a frozen reader or make the new empty P16 root reject that save solely because P16 cannot value the score. At the P16 valuation boundary, return a typed `unavailable`/refusal with the affected FilmId and reason (or adopt a separately versioned, reviewed normalization rule), leaving the stored score and all title/creator history intact. Do not silently skip the film, price it as zero, clamp without declared law, or award a partial catalogue value as if complete. Materialization of truthful identity/title should not itself require a valid valuation score. A RED must first prove a predecessor-valid finite out-of-range save loads and migrates, then isolate the P16 valuation refusal while proving state bytes and title provenance remain unchanged. Test a normal `[0,100]` path separately.

This is a design correction, not a new Owner economic choice. The provisional `$100,000` R2 and `$25,000` R1 coefficients are parent-adoptable once this admission/consumer boundary is made explicit and independently reviewed. No production source, Git index/ref, fixture, test, or game process was changed or run; the live repo remained clean.
