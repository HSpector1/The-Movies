## Structural and context gaps

V24 only checks envelope/state records and presence of technology and physicalPlans before the upstream calls. Those validators validate their own roots, not all Hollywood business, receipt, operations, development and account shapes. For example technology.ts:635 reads Hollywood identities via filter; physicalPlans.ts:302 maps identities and :422 searches receipts. A successful technology pass with empty research need not have visited each rival's operations at all.

The new owner proof calls receipts.filter, business lookup, facilities.some, workflows iteration, reservations.some, bindings access, development.projects.find, and period iteration/movements access. These are not all made safe merely by passing the upstream owners. V27's preliminary account checks cover only part of the required shape. A type cast is not admission.

A second consequential gap is lost context: save.ts:8527–8545 strips workflow setup and planRevision, and :8570–8609 does this for every rival before descending into V24. The shared disposal dependency helper explicitly reads setup.stageFacilityId and setup.priorWork. Calling it on that lowered state silently omits these retained dependencies. At V19, save.ts:8084 passes frozen.state without Hollywood/technology/physicalPlans, while the separate technology argument is typed only as access/adoptions and the plan array travels separately. This is not the full state expected by the new proof.
