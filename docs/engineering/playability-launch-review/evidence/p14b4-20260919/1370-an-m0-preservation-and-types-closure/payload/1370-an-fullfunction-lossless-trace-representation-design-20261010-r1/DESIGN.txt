NEW proposed accounting bounds the retained encoded packet (dictionary plus every reference/event frame and version/count framing) at2097152 UTF-8 bytes. These are different acceptance predicates. Keep16384 logical entries and65536 expanded UTF-8 JSON-row-plus-newline bytes unchanged; keep fatal complete-trace assertion and overflow diagnostic. Gameplay observer512/16384/2097152 is untouched.

Concrete minimal encoding proposal: a versioned byte-framed packet. Dictionary frame D<byteLength>:<exact UTF-8 bytes>\n. Call frame C<sequence>,<nameRef>,<detailRef>\n. Evaluation frame E<inputsRef>,<canonicalInputsRef>,<resultRef>,<contextRef>\n. Fields name/detail/inputs/result/context retain the EXACT original JSON.stringify field string; canonicalInputs retains its EXACT original string bytes, not a normalized or recomputed surrogate. Frame indices refer to existing dictionary entries only. Strings with newlines/colons/NUL/multibyte characters are unambiguous because dictionary bytes are length-framed. Same exact byte string may be reused across field types because decoding behavior is determined by the event slot. Events remain separate even if all fields repeat; calls keep original call-sequence numbering, separate call/evaluation lists retain exact original multiplicity/order. A tag tracks cross-kind append order for admission/accounting; current consumers need separate lists, so neither ordering is discarded.

Capture: produce the original expanded row first, exactly once with original stringify semantics, and check its UTF-8 bytes plus newline against65536 before compression. Extract dictionary field strings from this captured serialized snapshot (not by rereading mutable caller objects or independently stringifying getters). Canonical string is recovered exactly from the captured row's string field. The implementation needs an independently checked bounded splitter/parser for these fixed shapes; prefer using the parsed snapshot already produced by original JSON.parse, with byte-identical reconstruction explicitly tested, and STOP if exact original expanded-row reconstruction differs. Do not invent a generalized unqualified lossless parser. Dictionary equality is complete exact string equality, never digest-only or object identity. Plan all new dictionary entries plus event/version/index framing, then check encoded total and logical count before atomically committing any row. Pending dictionary strings for one row are bounded by that admitted expanded row. Overflow returns no successful row and remains fatal; no partial references/dictionary admissions. begin clears every table/frame/index/counter; end closes and returns immutable bounded trace handles. There is no filtering, sample, dropped payload, changed gameplay result or injected RNG operation.

Canonical input field deserves special care: storing only JSON.parse(canonicalInputs) or regenerating sorted JSON would weaken exact witness equality. Preserve the original canonical string and the original inputs representation independently, even if that reduces compression. Dictionary field reuse, not canonical substitution, is the proposed saving.

Consumer migration is real work, not a drop-in arrays claim. Expose callCount/evaluationCount, callAt(i)/evaluationAt(i), and ordered iterators. Each decode returns at most one original admitted row; compare off/on iterators in lockstep using exact expanded JSON, keeping no expanded full-trace array. Preserve original evaluation semantic comparison (inputs/canonicalInputs/result) and context binding. Ordering consumer should hold small integer event-index lists for selection and fetch source/evaluation rows on demand; it must not materialize expanded payloads with filter/map across the entire trace. Original duplicate-aware case/proposal arrays are decoded one source row at a time; context matching and existence/count/order checks use exact row/context bytes. At most two expanded admitted rows (2*65536 bytes of serialized scratch), plus one bounded current projection and fixed integer-index lists bounded by16384 entries, may be live for trace traversal. Index tables, dictionary and event descriptors are bounded by the packet and logical limits, with a separately stated implementation memory bound; retained serialized copies must all count if exported or retained. No eager expanded JSON packet or uncharged second trace array. Full GameState off/on comparison remains the original separate policy check.

Scope limitation: whole-field dictionary reuse may be insufficient because inputs/canonical strings can be unique. If evidence later demonstrates insufficient exact reuse, preserve the new STOP and review a specific further representation design. Expanded logical-entry or row failures remain failures regardless of compression.
