Keep this source package and its unfilled templates immutable after READY. Create a new unique exact-candidate directory; fill a new BINDING-DRAFT.json and concrete LAUNCH-SPEC.json, with current IDENTITY.json, GUARD-PROOF-ROLES.json, REPORT.md and PINS.json. Follow GUARD-TRANSITION.md for full admission and current scopes. No copied-root reading is authorized just by this template.

The binding starts status DRAFT_EXACT_REVIEW_PENDING_UNRUN, executionAuthorization false, and exactBindingReviewPath/Sha256/Decision null. SHA256 uses canonical JSON json.dumps(obj,sort_keys=True,separators=(',',':')).encode(). Let A={status,executionAuthorization,exactBindingReviewPath,exactBindingReviewSha256,exactBindingReviewDecision}. The execution semantic digest excludes exactly A. For the preflight receipt only, guardCoreSha256 excludes A plus {preflightReviewPath,preflightReviewSha256}; this prevents a self-reference. Fill the complete guard core first, issue the pinned independently accepted guard-core receipt, insert its pointer/hash, then compute the full execution semantic digest. The exact review binds both digests and the complete pinned preflight pointer. No receipt must contain a digest including its own hash.

Required source receipt: decision starts ACCEPT_SOURCE_ONLY_UNRUN and recorderSha256/supervisorSha256 match exact code. The accepted M0 source receipt uses decision ACCEPT_SOURCE_ONLY_UNRUN_REQUIRES_COMPLETE_RECORDED_EXACT_ROUTE and sourceSha256 matching accepted materializer. The independent exact reviewer returns decision ACCEPT_EXACT_FILLED_UNRUN and bindingSemanticSha256 matching the full execution semantic digest. The receipt should additionally name candidate path/raw binding SHA, guard-core SHA, launch-spec SHA, route source pins/source review, original materializer source/review, full guard proof hashes and exact argv. Parent separately adopts that concrete receipt without changing execution semantics.

Before adoption, create a new immutable versioned pre-adoption archive containing byte-identical copies of all six candidate files, hash/size/source-path inventory and an archive manifest. Create a separate ADOPTED-LAUNCH-SPEC.json that copies exact argv/environment/cwd and substitutes only the actual binding path/new raw checksum plus review/archive roles; this new file does not mutate the archived original launch spec. Independently review adopted bytes, archive equality, five-field delta, unchanged semantic, current guards and actual helper/source argv immediately before launch. That final adopted-preflight receipt is external, not inserted back into the binding. If freeze/current assumptions lapse, refresh admission and exact binding/review rather than changing pinned pointers.
