Status: **design only**. The Owner-approved, independently reviewed 1369-A r2 amendment authorizes a future, separately named 720-second Vitest / 750-second recorder observed acceptance route. This document neither assembles or statically approves a package nor admits a run. It applies only after a corrected, frozen ABC candidate has a reviewed source identity and protected ledger differences are resolved through their own evidence. Use route identity `OBSERVED_ACCEPTANCE_720_750_R1` consistently in the package manifest, runner, child binding, launch record, RESULT, five direct formal records, independent reviews, and comparator. Preserve the exact original `p13a-core-causal-01` seed and original `LEDGER_SEEDS` protected pins. A separate adoption seed requires separate named runs and does not substitute for p13a.

The old 300/330 r4/r5 observed TIMEOUTs and original-cap C0 adoption TIMEOUT remain failures under their original identity. R7 r2 600/630 observed completion and its descriptive comparator remain `EXPLORATORY_NOT_ACCEPTANCE`. Do not copy, edit, relabel, or admit those RESULTs or their types/clean prerequisites as new-route evidence. The 1369-A amendment review accepted procedure only, not source, runner, comparator or measurement. A route pass with still-false protected pins proves only that the observation completed; it does not repair 40→18, 48→42, explain C0→ABC causality, authorize repins, close 1363 or promote main.

## Versioned review and execution order

1. Independently review the corrected source freeze and causal/protected-pin evidence. Then independently statically review the **complete new package**: all file hashes, baseline delta, both 720,000 ms tokens, 750-second binding and real wait, identity everywhere, source/HEAD/index checks, original helper/seeds/pins, full observations/admissions/output, new prerequisites, recorder and cleanup. A r7 static ACCEPT is useful provenance, not this review.
2. With lane idle and no writer/postflight active, verify source, local/full origin HEAD, tree/index, free space, power, new paths and self/manifests. Run **fresh types** through the reviewed runner and lane. Admit only actual TypeScript child and recorder zero, no timeout/reporting errors, exact guards/formal records/artifact hashes, and verified cleanup. Pin its new RESULT SHA.
3. Recheck all preconditions. Run **fresh clean p13a** against the same package and accepted types SHA. Require actual child/recorder zero, one Vitest PASS/zero FAIL, completed/source-postflight true, exact source/seed/416 identity, 416 contiguous weekly rows, zero observed-only phase/industry rows, all eight progress/profile marks, protected actual-pin values recorded without repin, complete artifacts/formal pre/postflight and cleanup. Pin its new RESULT and data SHA. If the corrected source is expected to satisfy protected pins, verify every original comparison is true before continuing toward ledger acceptance; retain any mismatch as an unresolved ledger failure.
4. Recheck preconditions and receipt hashes. Run **fresh observed p13a** through the single lane, bound to the accepted new types and clean SHAs. Require new classification and 720/750 values in both binding and RESULT, actual child and recorder zero, `timedOut=false`, empty reporting errors, `allGuardsExact`, live/source postflight exact, one Vitest PASS/zero FAIL, complete 416 contiguous weekly rows and 416 phase plus 416 industry rows, eight progress/profile marks, final fields and all artifact/formal SHA checks, process-group cleanup verified/leader reaped/no survivors. Preserve and stop on a timeout, partial data, child failure or guard failure; never auto retry or reinterpret it.
5. Have an independent reviewer rehash the complete new package, every source member, types/clean/observed RESULT and artifact, formal files, launch/binding, status, progress, data field set, 416-week counts, postflight and cleanup. Record the exact observed RESULT SHA and issue a separate complete-observed acceptance document binding REVIEW and RECEIPT SHA. This audit precedes any comparator input admission.
6. Build a **separately versioned** `OBSERVED_ACCEPTANCE_720_750_R1` comparator/admission gate from the r7 r3 comparator logic. Independently statically review its exact code and adversarial refusal checks before running it. Bind the new package/runner/source/kit hashes, 720/750 actual settings, exact types/clean/observed RESULT paths and SHAs, new audit document/review/receipt, original seed/pins, horizon, identity, commands, formal pre/postflight, artifact/progress/Vitest/cleanup status, and clean→observed prerequisite chain **before opening either data file**. Refuse missing files, forged bounds, repinned source/expectations, stale or mismatched audit, old r7 classification, incomplete run, or changed output schema. Run it fresh to compare every shared clean/observed field recursively, including each weekly row, final state digest, actual pins, ledger rows, market, employment, industry receipts and retirements. Report first differing path/week and exact SHA/byte accounting; phase/industry arrays are observed-only diagnostics of length 416. Optional historical C0/r5 context must remain explicitly separate and cannot satisfy admission or prove causality. Independently audit the comparator result before claiming same-source observer neutrality.

At every stage, stop at the first failed prerequisite and preserve original partial artifacts. Recheck source and receipt pins immediately before each consumer, because a successful earlier mode does not carry authority across a changed package or HEAD. A later documentation-only HEAD may advance between modes if the runner explicitly checks a fresh local/origin equality and the pinned source/kit/runner remain byte-identical; no result is silently rebound. A successful 720/750 neutrality comparison remains one bounded ledger observation on one corrected source/seed. It is only one input to the wider 1363 and Owner1368-O gates.
