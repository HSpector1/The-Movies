## 6. Exact NO-GO criteria

Any one condition below is sufficient for **NO-GO**:

- P05 is WIP, technically sealed but Owner-unaccepted, or accepted only verbally.
- A final SHA, branch, changed-path set, test result or version fact is absent.
- A dirty tree, local-only commit, stale generated consumer or WIP branch is required as authority.
- Wrap/resource release, Post allocation/waiting or post-Wrap ownership remains ambiguous.
- A current picture/facility/person can be found only by title, array order, nearest transform or
  first match.
- The world route requires prior Production Rail/project selection.
- Multiple Stages or Post facilities can cross-wire identity, presence or actions.
- Contract generation can silently flatten an unsafe union or verification does not bind the exact
  Unity consumer.
- The final P05 workspace/rail/menu/input/Back/Locate/snapshot/evidence owner is unknown.
- P06 would need to modify P05 architecture before it can define its own bounded Wave 0.
- Any plan relies on Unity-side simulation, continued uncommitted auto-release, result preview,
  fake quality, duplicate marketing or another hard exclusion.
- The proposed P06 proof has seven Visual Oracle scenes, crosses into result interpretation, or
  treats a machine-green checkpoint as Owner acceptance.

**Current adjudication: PRE-P05 OWNER ACCEPTANCE — NO-GO.** The documentation package can be
provisionally ready while implementation remains blocked.
