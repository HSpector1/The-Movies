## Non-negotiable implementation law

```text
TYPESCRIPT PUBLISHES CURRENT LEGAL FACTS AND CHOICES
→ UNITY HOLDS ONLY A REVERSIBLE PRESENTATION DRAFT
→ TYPESCRIPT REVALIDATES THE EXACT DRAFT AND MINTS/RETURNS CURRENT COMMIT AUTHORITY
→ UNITY SUBMITS THE CURRENT OPAQUE INTENT ONCE
→ TYPESCRIPT RETURNS AN AUTHORITATIVE SUCCESSOR OR REJECTS WITHOUT PARTIAL STATE
→ THE HOST APPLIES ITS EXISTING PERSISTENCE POLICY; IT MUST NOT CLAIM AN AUTOSAVE IT DID NOT PROVE
→ UNITY REPAINTS THE AUTHORITATIVE SUCCESSOR
```

TypeScript owns identity, role requirements, slate/result truth, Fit, visibility of talent facts,
availability, employment, assignments, costs, package assessment, legality, Greenlight, formation,
time, RNG, queue, and save. Unity owns composition, camera, world selection/highlight, portraits,
input, animation, exact presentation draft memory, and responsive behavior.

The current Unity `StudioBridgeIntentOption` cannot express a player-authored slate or package: it
contains only an opaque intent plus labels/IDs, and the request submits only that intent ID.
Fable must extend the TypeScript-owned projection/validation/intent boundary before presenting
interactive casting in Unity. Do not encode the missing rules in C# and do not hand-edit generated
DTOs.

### Role-pool warning

Current camera-test planning admits only primary Actors, and ordinary browser Package pickers
discover people through primary-role pools. Direct Core Greenlight's discipline check is broader:
it checks that the relevant discipline skill object exists, and every current `Talent` has all four
discipline skill objects. P04A should preserve the surfaced primary-role discovery contract and
exact Core revalidation; it must not widen the candidate pool ad hoc in Unity. Broad
multi-hyphenate discovery is a later explicit UX/authority decision.

### Sealed Unity gap statement

At the sealed commit, Unity can truthfully show high-level First Film Journey stages, authoritative
auditionees in the Casting zone, generic building attention, correct decision pausing, opaque
intents, stale rejection, and production formation. It cannot truthfully show:

- exact screenplay header/genre/writer/role requirements;
- session capacity/slate/due/result details;
- candidate OVR/Fit/genre/Star Power/availability/cost/public supporting signals;
- actor evidence ranges;
- Director/Craft candidate pools;
- editable role slots or a package draft;
- aligned comparison;
- package assessment/cost/exposure/blocker review; or
- an exact player-authored Greenlight package.

Generic `people` presence and intent label/detail strings are insufficient. Build the TypeScript
projection/intent seam first.

# C. Casting Office Inspector Anatomy

Use the accepted CP10A shared building-inspector shell and Project: Studio visual identity. Do not
create a separate Casting art system. The following is content hierarchy and responsive geometry,
not permission to override accepted tokens.

## C1. Desktop shell

- Target width: approximately 380–440 CSS-equivalent px within the shared inspector envelope.
- Maximum height: approximately 70–76% of the usable viewport; one internal scroll owner if needed.
- Outer padding: 20–24 px; section gap: 12–16 px.
- Title: 22–24 px equivalent; state line and body: at least 16 px; secondary metadata: at least
  14 px with strong contrast; button labels: 16 px.
- Minimum interactive target: 44×44 px equivalent with visible keyboard/controller focus.
- One primary filled action, at most two secondary visible actions, remaining routes under a
  clearly labelled More/Deep route—not hidden critical actions.

## C2. Header and status grammar

Header order never changes:

1. `Casting Office`;
2. one semantic state icon plus uppercase/plain state phrase;
3. exact current picture title and genre, or `No screenplay ready`;
4. `Focus` as explicit camera action; and
5. current blocker badge only when a blocker exists.

Use icon + text + shape/border, never color alone:

- neutral/idle: open door/empty slate;
- ready: screenplay/slate check;
- active: camera/slate motion icon;
- waiting: clock/queue;
- decision: review mark;
- blocked: stop/alert shape;
- formed: clapper/company check only in the immediate accepted receipt.

## C5. Narrow inspector

# D. Casting Workspace Anatomy

The Casting workspace is a single retained-lot host with mode changes inside it, not a sequence of
unrelated pages. Its persistent frame keeps project identity, role state, and commitment status
visible while the main canvas changes from planning → evidence → package → review.

## D1. Wide layout

At ≥1200 px usable width, use the accepted retained-workspace envelope:

- right-anchored; maximum `min(1120px, 82vw)`;
- 24–32 px viewport inset; maximum height near `88dvh`;
- neutral 0.35–0.45 scrim; click on scrim does not commit or cancel;
- one internal scroll owner; sticky identity/header and bottom action region; and
- background lot remains mounted/visible but world input is suspended.

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ CASTING · THE FADING CONSTELLATION · DRAMA      Package draft · not committed│
│ Writer Mae Caldwell     Camera tests: complete      [Locate Casting] [× Back]│
├──────────────────┬──────────────────────────────┬─────────────────────────────┤
│ ROLE / PROJECT   │ CANDIDATES / CURRENT TASK    │ SELECTED PERSON             │
│                  │                              │                             │
│ Writer · locked  │ [Search] [Filter] [Sort Fit] │ portrait  NAME              │
│ Director   Empty │ Candidate row                │ DIRECTOR OVR 72 · FIT 68    │
│ Lead       Ada   │ Candidate row                │ expected band / evidence    │
│ Antagonist Empty │ Candidate row                │ 2 strengths · 1 concern     │
│ Support    Empty │ Candidate row                │ availability / fee          │
│ Craft      Empty │ Candidate row                │ [Choose] [Compare]          │
│                  │                              │ [Locate] [Profile]          │
│ Project/history  │ auditioned first, not winner │                             │
├──────────────────┴──────────────────────────────┴─────────────────────────────┤
│ Readiness: 1/5 · Antagonist, Support, Craft missing      [Review Greenlight] │
└──────────────────────────────────────────────────────────────────────────────┘
```

Approximate usable-content split:

- role/project rail: 20–23%;
- candidate rail: 39–44%;
- selected dossier: 33–37%; and
- gaps/dividers: remainder.

These allocations may flex with localization; never shrink the dossier/body below readable text
just to preserve percentages.

## D2. Persistent project header

Always visible:

- `Casting` eyebrow and exact title/genre;
- locked writer;
- current camera-test state (`Not run`, `Queued`, `Due Week N`, `Results ready`, `Complete`);
- `Package draft · not committed` until accepted Greenlight;
- project switcher only when multiple current projects exist;
- explicit `Locate Casting`; and
- Back/Close that returns one layer.

Changing project is a deliberate action and restores each project's presentation context only if
still current. It never substitutes by matching title or position.

## D3. Audition-planning mode

```text
Role rail          Six-read slate                         Consequence
Lead 0/2           [Candidate A] [Candidate B]            1 week
Antagonist 0/2     [Candidate C] [Candidate D]            1 shared slot
Support 0/2        [Candidate E] [Candidate F]            No audition fee
                   N unique people                        No signing/hold

                                      [Cancel] [Start one-week camera tests]
```

- No preselection.
- Selecting a candidate opens the dossier but does not add them; `Add to Lead test` is explicit.
- Same person may appear in several role pairs; within-role duplicate is rejected.
- Completeness text names `Choose 2 for Lead`, not a generic disabled button.
- `Start` remains disabled until exact local shape is complete, then TypeScript revalidates/mints
  current commit authority; stale rejection preserves all six choices.
- Package-direct route is visible but secondary and clearly says `Continue without tests`.

## D4. Auditions-underway mode

- Role rail shows the six stored reads and each unique person's attendance state where published.
- Main area shows facility, slot, started week, due week, one-week consequence, and `No results yet`.
- `Locate candidate` appears only for a current world anchor.
- No active cancellation control.
- `Back to lot` returns while the session continues.

## D5. Results-review mode

- Role rail shows Lead/Antagonist/Support, each `2 results`.
- Main area shows two candidate result cards for the selected role.
- Dossier and Compare work immediately; no separate administrative acknowledgement page.
- Persistent copy: `Camera tests add evidence. They did not select the cast.`
- Primary `Continue to Casting` performs exact acknowledgement and opens blank package draft for
  that project only after accepted successor.
- If blocked, `Finish casting review` commits acknowledgement and leaves the blocker/remedy in the
  Casting context.

## D6. Package mode

- Writer remains locked and visible.
- Role rail adds Director and Production/Craft Lead around the three actor roles.
- Actor roles retain role-specific audition badges; Director/Craft never show fake test results.
- Candidate selection updates only local draft and a TypeScript-published validated assessment.
- Empty/incomplete/conflicting/stale roles explain why Review Greenlight is unavailable.
- `Review Greenlight` is a navigation action; it does not commit.

## D7. Responsive layout

At roughly 840–1199 px:

- role rail becomes a compact 168–200 px column;
- candidate rail and dossier alternate via `Candidates | Details | Compare` segmented control;
- selected role/project header remains sticky; and
- action bar remains visible.

Below roughly 840 px:

- retained workspace becomes full-height bottom sheet/full-viewport layer over the still-mounted lot;
- role rail becomes horizontal/paged role strip;
- candidate list is one column;
- selected dossier is a pushed layer with Back to the exact candidate list position;
- Compare supports two pinned candidates at a time, not squeezed 3–4 columns; and
- project/role/readiness plus commit state remain visible without relying on hover.

No breakpoint hides critical cost, availability, blocker, or commit consequence in a tooltip.


or:

```text
[Back to Package]                   [Queue greenlight]
```

- Rejected/stale action: no mutation, keep complete draft/context, focus blocker/error, request a

## G6. Immediate world response

After accepted immediate formation:

- Casting selection may remain while inspector atomically changes to the successor/receipt;
- exact company members and production identity come from the new snapshot;
- people move only according to authoritative presence/routing;
- one concise receipt says what was committed and where the picture goes next;
- no camera cut, auto-Focus, celebration that implies box-office success, or Production control; and
- Back returns through the normal origin stack.

## H1. Draft persistence statement

Current browser `Assembly` package selections are local React `Draft` state until Greenlight. They
are reversible and safe, but they are not in GameState/SaveFile. P04A must not present them as
durable attachments or holds and must not silently invent save persistence in Unity. If the Owner
later wants package drafting to survive application save/load, that is a separate authoritative
state campaign.

# P04A hostile-review acceptance summary

P04A fails if any of the following is true:

- the generic white memo remains the ordinary way to start/complete Casting;
- Selecting/inspecting a person assigns them;
- Unity calculates or explains Fit/result/package law from local thresholds;
- tests are mandatory, free, a talent reroll, a hold, or an auto-winner;
- an auditioned unavailable person silently disappears or is substituted;
- role slots differ from current TypeScript truth;
- ordinary Crew/Extras are invented;
- Package draft is described as committed/persisted before Greenlight;
- Greenlight hides exact cost/capacity/blocker/current company;
- set/stage demand is falsely used as a current Greenlight gate;
- a queued Greenlight appears to have formed a production or committed resources;
- Back loses project/role/filter/pins/scroll/camera/selection;
- the lot remounts or the camera moves without explicit Focus/Locate;
- stale rejection clears the draft or partially mutates state;
- actor Fit presents public supporting signals as a complete causal explanation, or hidden-actual
  `teamDirection` reaches the player-facing package;
- desktop body text falls below 16 px equivalent, a primary target falls below 44×44 px, or narrow
  layout clips actions/hides current cost, availability, or blocker information;
- save/load rerolls or duplicates a Casting session; or
- the checkpoint proceeds into Production/Shooting.

It passes when the Owner can begin at the lot, understand Casting locally, deliberately buy or skip
camera-test evidence, compare people in the exact role context, build a reversible current package,
understand why a choice/Greenlight is consequential, commit once, and immediately see the exact
studio-world response.
