## Event and pending-decision provenance

The implementation keeps two authorities distinct:

| Player path | Exact owner |
| --- | --- |
| Newly surfaced review after **Sim to next event** | Complete valid Casting receipt plus the exact still-owned App event session and current Core decision |
| Review already pending on load, return, or current state | Current Core decision plus the exact current review card and action |

A malformed or stale event receipt cannot downgrade into the pending path during the same gesture.
An already-pending review needs no synthetic receipt merely to become playable. Selecting Casting
opens the bounded review only while that strict current context exists; genuine no-review state
retains the established Casting Room route.

Malformed or throwing current-decision adapters fail neutral on the Lot. They cannot use a failed
strict selector as evidence that the deep Casting route is legal, cannot select another review,
and cannot mutate or resave the current bytes.
