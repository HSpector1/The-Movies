Authority: `OPS-P13A-PERFORMANCE-CORRECTION-20260911-02`. Feature scope remains frozen. The new gate uses fresh matched accepted/P13 median and p95 ratios of at most 1.05 for both complete Save and load-ready; these diagnostic profiles are not that acceptance test. Original stopped evidence remains untouched.

The first pair profiles exact accepted `592e926bfbf4574df94b38fc8dd594fc5df2ac8d` and stopped P13 `1bba6645265ab59395c126b77afc95401cb7a29e`, reusing the retained generated three-record week-6,240 fixed libraries in fresh private stores. The common harness performs one unprofiled warmup load/Save followed by one V8 CPU-profiled load/Save. Public store operations, coordinator recovery and first snapshot carry wall timers. No product source was instrumented. Both runs passed exact digest/week/catalogue/inactive-record checks and closed their stores and locks.

The stopped technology validator performs **6,435,042 historical-film predicate visits per invocation** for this state: 3,586 technology production rows, 3,587 Hollywood films and 3,579 historical searches. This is an exact read-only count of its existing short-circuit algorithm, outside measured phases; it is not a count of validation invocations.

The profile attributes 1,117.31 ms load / 374.48 ms Save inclusive CPU to `validateTechnology`, including 921.20 / 314.93 ms in its historical-film callback. Every `validateSaveV20` self position tick points to the same call site, emitted line 15,928 (`validateTechnology(typed.state)`), rather than a separate envelope or serialization traversal. V8 can attribute optimized/inlined work at that call site, so those sampled costs must not be interpreted as independent additive components. Direct diagnostic-only try/finally instrumentation subsequently measured actual function wall totals/counts before and after the smallest lookup correction.

Inherited CPU costs remain visible: `stableStringify` is 2,663.24 ms accepted versus 2,678.87 ms stopped P13 on load, and 904.42 versus 899.26 ms on Save. `validateHollywood` is 4,001.71 versus 3,959.24 ms on load. Store durable-write wall time is 74.180 ms accepted versus 67.666 ms stopped P13 in these profiled Saves. These one-off diagnostic values and profiler-control overhead do not supply acceptance percentiles or justify a general P12 optimization.
