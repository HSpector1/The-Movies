# Studio player verification

Original Studio checklist. Reference inspiration and licensing limits are in the source
inventory. This skill grants no execution authority and cannot lift the gameplay stop.

For a future authorized player-facing slice select the existing journey/harness in its
checkpoint. Keep the Studio Lot primary and preserve the adopted Owner design. Record
candidate, visible behavior, starting state, input sequence and expected money/ownership/
history effects before execution. Preserve required end-to-end coverage and original budgets.

- Exercise ordinary boot, the first actionable screen, changed player verb, save/reload and
  affected transitions. Check keyboard/pointer focus, dismiss/back and repeated input.
- Inspect actual camera/viewport screenshots for canvas/WebGL work; DOM text alone cannot
  prove visibility. Check HUD obstruction, legibility, resize and reduced motion where affected.
  Use existing capture tools; install no graphics/runtime toolkit.
- Check authoritative UI/core agreement, actionable failures and atomic refusal. Preserve the
  caller on failed actions; check disposal after close/reopen where affected.
- Use existing preflight and sole lane. Browser, native and platform observations are separate.
  A headless assertion does not prove visible native input or player enjoyment.
- Report concrete reproduction, visible symptom, source owner, evidence identity, first
  failure/unreached checks and remaining Owner acceptance. Diagnostic images and source-only
  tests cannot complete a player journey.

Find actual owners, regressions and entrypoints through `docs/development/LESSON_MAP.md`.
