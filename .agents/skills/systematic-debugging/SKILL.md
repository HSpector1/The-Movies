# Systematic debugging — Studio adaptation

Adapted 2026-10-18 from obra/superpowers at the inventory pin, under the accompanying MIT
LICENSE. This self-contained version replaces upstream examples, executable helpers,
cross-skill TDD requirements and automatic human-discussion loops.

1. Read the exact failure, candidate identity, first cause and unreached assertions. Retain
   failed output and budgets. Select the relevant LESSON_MAP symptom before edits.
2. Trace the real producer and consumer boundaries. Compare a working case and recent changes;
   distinguish schema, input week, caller state, harness, environment and product law.
   Do not invent historical state or hashes, retime events or normalize evidence away.
3. State one cause supported by observations. Use the smallest isolated diagnostic or existing
   regression that distinguishes it. Respect the sole lane, execution freeze and Owner pause;
   this skill grants no execution authorization.
4. Correct the shared cause once. Preserve validation and independent test ownership. Add a
   narrow regression when justified; trivial instruction edits need no unrelated suite.
5. Qualify affected complete files at the authorized gate and original budgets. Record
   functional assertions separately from timing. Unreached checks stay unreached. Read
   `../verification-before-completion/SKILL.md` before a success claim.

Repeated failed hypotheses require a fresh examination of evidence rather than stacked
speculative patches. Resolve routine engineering choices within the current order. Ask the
Owner only for a genuinely missing decision, permission or prerequisite. Do not introduce
polling, logging services, reviewers or runtime packages through this skill.
